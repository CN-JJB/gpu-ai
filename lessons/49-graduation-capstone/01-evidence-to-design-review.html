毕业 Machine Design Capstone — 你的结论能经得住追问吗？

1. 最后不是交一张配置单

“RTX xxxx + 64GB RAM + 2TB SSD”

这只能说明你列了零件。

毕业交付物要回答：

为什么这个 workload
需要这些约束
→ 每个关键结论由什么 Evidence 支撑
→ 如果失败，怎么改
→ 什么证据出现后才升级

2. 先继承 Slice 48

known FAIL → REVISE
critical UNKNOWN → BLOCKED
all required PASS → ACCEPT
毕业项目不要求一定 ACCEPT。能证明“现在不该买”也是合格工程结论。

3. Experiment 91 是底座，不是毕业报告本身

Experiment 91 已经检查：

Gate
+ PASS / FAIL / UNKNOWN
+ source

毕业层还要问：

这个 source 真的足够证明这个 claim 吗？

4. Claim 和 Evidence 一一对齐

例如：

Claim:
目标 backend 能稳定跑这个模型

Evidence:
exact runtime version
exact model hash
actual run log
benchmark manifest

只有“PCIe 里看见 GPU”并不够。

5. 不同证据能证明不同东西

官方文档
→ 厂商发布规格/支持声明

runtime log
→ 这次真实环境识别/执行

benchmark trace
→ 这套 workload 下的测量结果

seller listing
→ 卖家声称了什么

卖家说 24 GiB，不等于你已经测到 24 GiB。

6. 毕业报告必须写 Non-claims

例如你得到：

10 分钟 sustained benchmark PASS

它并不能自动证明：

一年 24/7 不会坏

所以报告要主动写：

What this evidence does NOT prove

7. Revision 不是“换更好的”

如果 30 GiB 目标装不进 24 GiB：

Revision A: smaller quant/model
Revision B: lower context/concurrency
Revision C: different GPU
Revision D: multi-GPU

每个 Revision 都必须回答：

修哪个失败？
改哪个变量？
需要补什么新 Evidence？
带来什么新成本/风险？

8. Upgrade roadmap 不是购物车

差的路线图：

以后换更强显卡
以后加内存

好的路线图：

当 VRAM headroom < target
→ 再评估模型/量化/多卡

当 serving TTFT p95 超过 SLO
→ 先测 queue/KV/compute
→ 再决定升级哪一层

9. 把“现在、下一步、以后”分开

NOW
当前目标必须完成的修改/证据

NEXT
有明确触发条件的下一能力

LATER
只有测到对应瓶颈才做的优化

10. 三种毕业案例都可能正确

ACCEPT

all required gates PASS
all material claims traceable
→ ACCEPT

REVISE

known VRAM hard fail
no blocking unknown
revision directly addresses it
→ REVISE

BLOCKED

modular PSU cable compatibility unknown
→ BLOCKED
→ do not buy yet

11. Rubric 不允许“平均掉致命错误”

写作再漂亮，也不能补救：

fatal gate FAIL
evidence missing
decision inconsistent

12. 最终结构

goal/workload
→ model dossier
→ machine architecture
→ hard-gate matrix
→ Evidence index
→ benchmark/quality/SLO
→ TCO/risk
→ revisions
→ upgrade roadmap
→ non-claims
→ ACCEPT / REVISE / BLOCKED

13. 你真正毕业的标志

不是记住最多型号，而是遇到一台没见过的机器时，你仍然能：

定义目标
→ 找证据
→ 识别硬门槛
→ 测量
→ 拒绝猜测
→ 修改设计
→ 解释边界
这就是 transfer。

学生闭环 — Graduation Machine Design Capstone

硬件门槛：L0 可以完成完整设计评审；真实毕业报告 Experiment 93 需要你未来选定的 learner-owned target。

成本：0 元设计主路径；毕业不要求为了“通过”而购买硬件。

风险：safe。毕业结论允许 ACCEPT / REVISE / BLOCKED；证明“不该买”同样是合格结果。

能力目标

  • 把整门课程的模型、GPU、平台、Serving、质量、TCO、二手风险串成一份可追溯设计。
  • 任何 material claim 都能指出 Evidence；任何 Evidence 都明确它不能证明什么。
  • 面对失败或未知，能提出最小 revision 与下一条需要获取的证据。

小实验 / 反馈

先做 Experiment 92：graduation design review。以后开始正式学习并选定自己的机器目标后，再做 Experiment 93：real graduation report。

Retrieval Practice

  1. 为什么一份漂亮配置单不等于毕业设计？
  2. 一个 critical UNKNOWN 为什么不能靠“应该没问题”变成 PASS？
  3. 如果 24 GiB 卡无法满足目标 context/concurrency，你至少能提出哪四种 revision？
  4. 什么叫 evidence-triggered upgrade，而不是“以后有钱就换更强卡”？
  5. ACCEPT、REVISE、BLOCKED 三种毕业结论分别需要什么逻辑条件？

完成证据

提交完整 Machine Design Review：

goal/workload
→ model architecture dossier
→ machine hard-gate matrix
→ Evidence index
→ benchmark / quality / serving SLO
→ power / thermal / storage / host RAM
→ TCO / secondhand risk
→ revisions
→ evidence-triggered upgrade roadmap
→ non-claims
→ ACCEPT / REVISE / BLOCKED

如果尚无真实机器，所有需要真机的数据明确标记 NOT-YET-MEASURED，不得用 synthetic 结果冒充。

如何迁移

真正的 transfer 是换一张从没见过的 GPU、一个新模型、一个新 runtime 后，你仍然会：定义目标 → 找一手资料 → 建模 → 测量 → 判断 Evidence → 修改设计。
