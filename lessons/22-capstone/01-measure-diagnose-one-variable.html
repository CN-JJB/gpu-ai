Slice 22 — Capstone：不是“调最快”，而是“知道为什么变快”

1. 先锁死四个身份

Hardware
Runtime
Model artifact
Workload

模型必须记录 SHA256。Runtime 必须记录 commit/build。否则今天的 42 tok/s 和明天的 45 tok/s 根本不知道差在哪。

2. Baseline 至少要有 PP 和 TG

指标主要在问
PPprefill / 大矩阵 / attention kernel 怎么样？
TGdecode / 权重与 KV 流量怎么样？

再记录：

  • 显存/working set；
  • 温度；
  • 功耗；
  • backend startup log；
  • raw JSON。

3. 第一次真正做“诊断”

装不下

capacity problem
→ quant / KV / context / sharding

TG 慢，而且接近 bandwidth roof

decode bandwidth problem
→ weight bytes / backend memory traffic
→ maybe speculative

PP 慢，TG 还可以

matrix / attention kernel problem
→ backend / FA / datatype path

短 context 快，长 context 明显掉

KV / cache / memory pressure

单用户快，多用户 TTFT 爆炸

queue / slots / batching

双卡只快一点

interconnect / split / imbalance
重点：优化选项不是菜单里随便点一个，而是由 baseline 证据触发。

4. 每次只改一个变量

合法：

A: -fa 0
B: -fa 1

合法：

A: KV f16
B: KV q8_0

不合法：

A: old build + Q4 + FA off + 4k
B: new build + Q5 + FA on + 16k

第二种即使更快，你也不知道为什么。

5. 开跑前先写成功标准

例如 FA：

目标：
PP +20%以上
TG 不要求明显变化
显存不能造成新 OOM
correctness 正常

如果最后：

PP +31%
TG +2%

正确结论是：

FA mainly improved prefill path;
decode remains limited elsewhere.

不是：

FA makes this GPU 31% faster.

6. 负优化也是有效结果

candidate:
PP -4%
TG +0.5%

如果实验条件控制正确，这已经告诉你：

this optimization is not useful
for this workload/build/hardware

这比网上复制“必开参数”有价值得多。

7. 四个生态只换命令，不换科学方法

  • NVIDIA：CUDA / nvidia-smi
  • AMD：HIP / rocminfo / amd-smi
  • Apple：Metal / unified-memory evidence
  • Intel：SYCL / Level Zero / XPU

统一流程仍然是：

profile
→ baseline
→ hypothesis
→ one variable
→ A/B
→ interpretation

8. 最终毕业标准

你不需要有 5090，也不需要跑出排行榜第一。

你需要拿自己的硬件证明：

我知道它现在为什么是这个速度
我知道我改了什么
我知道哪个指标应该变
我有原始数据证明它到底变没变
我知道下一步该测什么

这才是前面 21 个 Slice 最终汇合的能力。
