Hardware Decision · L0→L2

硬件决策不是排行榜：Fit → Support → Roofs → Evidence → TCO

买本地 LLM 硬件最危险的习惯，是先搜“显卡性能排行”。正确顺序相反：先排除根本做不了的，再比较理论上限，再看真实证据，最后把整机成本和风险算进去。

Prerequisite Check

你应理解显存 fit、memory bandwidth、matrix/general compute、四厂商软件链。无需会财务模型。

真实问题：为什么一张“性价比最高”的卡可能对你完全没价值？

因为你的目标可能要求 24 GB 显存，而榜单第一只有 12 GB；或者目标 runtime 不支持；或者卡便宜但需要换 PSU/机箱/散热；或者 benchmark 来自不同模型/量化，根本不可比。

1. Fit 是 hard gate

weights
+ KV cache
+ runtime buffers
+ concurrency
+ safety margin
<= usable accelerator memory ?

如果不成立，你只有四类选择：更小模型/更激进量化；缩短 context/并发；部分 CPU/offload/多 GPU；换更大内存硬件。不要跳过这一步比较 token/s。

2. Support 是第二个 hard gate

支持不是品牌级 yes/no，而是：

exact device
× OS
× driver/runtime version
× application backend/build
× model/quant kernel

只有这条链成立，硬件规格才可能变成应用性能。

3. Roofs：在跑 benchmark 前先知道“最多可能被什么限制”

两个最常用的粗上限：

  • Compute roof：目标运算类型的可持续计算能力；
  • Memory roof：可持续内存带宽 ÷ 每单位输出需要搬运的有效字节。

LLM prefill 常更容易提高算术强度；小 batch decode 常更接近 memory-bound。roofline 不是实测值，它只帮助你判断“再加算力有没有可能有用”。

4. Evidence：从弱到强

证据能说明什么不能说明什么
厂商规格容量/带宽/feature 的官方上限你的应用速度
第三方 benchmark相似配置可能范围你的 exact build/quant
同协议可复现 benchmark目标 workload 实际 PP/TG未来所有 workload
质量+性能+功耗更完整 tradeoff购买风险/卡况
你自己的验卡证据这张具体二手卡的状态市场所有同型号卡

5. TCO：显卡价格只是第一行

TCO ≈
GPU purchase
+ PSU / adapter / motherboard / riser
+ case / cooling
+ electricity
+ storage/RAM upgrades
+ failure / return / repair risk
+ time cost
- resale value (uncertain)

不需要把时间成本精确换成人民币，也要把它作为风险显式写出。

Worked Example：900 美元 3090 vs 700 美元“便宜数据中心卡”

假设两者都可能满足模型容量。第二张便宜 200 美元，但需要服务器风道、特殊供电、当前 backend 验证，还可能没有显示输出。决策应拆：

  1. 两者都通过 fit 吗？
  2. 目标 runtime support 哪个更确定？
  3. 整机附加成本多少？
  4. 噪声/功耗是否满足居住环境？
  5. 真实 PP/TG/quality 差距？
  6. 退货/维修/转售风险？

便宜 200 美元只有在这些额外代价没有超过差额时才是真便宜。

6. Hard gate 与 soft preference

把条件分两类：

  • Hard gate：不满足就方案无效，例如 VRAM 不足、runtime 不支持、PSU/机箱装不下。
  • Soft preference：满足越多越好，例如更静音、更省电、更便宜、更易转售。

不要用加权总分让一个严重 hard failure 被其他优点“平均掉”。

7. Unknown 是合法状态

不知道某卡当前 ROCm 支持、卖家没给 hotspot 截图、benchmark 协议不清楚时，正确值是 UNKNOWN/BLOCKED，不是“估计差不多”。决策质量来自拒绝伪精确。

Why it matters

  • 先 fit/support 可以省掉大量无意义 benchmark 比较。
  • roof 帮你判断优化方向，避免只追峰值 TOPS。
  • 证据等级让论坛传闻不会和自己的测量同权。
  • TCO 防止“垃圾价显卡”变成“昂贵整机坑”。
  • hard gate/unknown 让决策可审计，而不是凭感觉。

常见误区

  • “性能/价格最高就是最优”——可能 fit/support 失败。
  • “显卡只要能插上就行”——PSU、lane、风道、连接器都可能是 hard gate。
  • “网上有人跑过，所以我也能”——软件/版本/型号可能不同。
  • “总分够高可以弥补一个缺点”——hard gate 不能被平均。
  • “不知道就按乐观值算”——unknown 应阻塞高风险结论。

小实验

任选三个候选 GPU，做一张没有“总分”的 decision sheet。先列 hard gates，再列 soft preferences；任何 unknown 单独标红。只在三个都通过同一 hard gate 后比较性能/价格。

预期观察：很多排行榜候选会在性能比较前就被淘汰，剩下的比较更少、更干净。

无硬件路径

本课完全 L0。你只需要目标模型假设和公开规格/当前支持文档。真实 benchmark 以后进入实验阶段再填。

排错

  • 候选太多：先收紧 hard gates（VRAM、预算、功耗、平台）。
  • 不同 benchmark 无法对齐：降级为参考，不做数值比值。
  • TCO 不知道怎么估：先列项目与范围，别强求单点。

Retrieval Practice

  1. 为什么 fit 和 support 必须在性能比较前？
  2. compute roof 与 memory roof 分别回答什么？
  3. 举三个 hard gate 与三个 soft preference。
  4. 为什么网上 benchmark 不能与自己的同协议 measurement 同权？
  5. 显卡 purchase price 与 TCO 有哪些常见差额？
  6. 什么时候 UNKNOWN 应直接阻塞购买判断？

Decision Rule

任何 GPU 候选必须按 Fit → Support → System feasibility → Comparable measurement → Quality → Cost/risk 顺序升级证据。排行榜只能用来发现候选，不能替代决策。

Transfer

这套 gate 思维可以迁移到模型选择、runtime 选择、NAS/服务器、甚至 SSD/RAM 采购：先满足 hard constraints，再优化 soft tradeoff。

Decision Dossier：先写 Gate，再写候选

为了避免看到喜欢的硬件后倒推理由，先冻结你的目标：

target model / quant:
target context:
target concurrency:
minimum acceptable PP/TG:
required OS/runtime:
physical limits:
power/noise limits:
total project budget:
evidence confidence required:

然后才把候选逐个放进同一张 gate 表。这样“这卡很便宜”“那卡 TOPS 很高”都只能影响对应栏，不能重写你的目标。

Worked Example：大显存但软件 UNKNOWN，应该排第几？

假设候选 A 容量、带宽、价格都很好，但目标 backend 对 exact device 的支持尚未确认；候选 B 纸面性能较低，但 software chain 已有高质量 evidence。正确表述不是“B 一定更好”，而是：

A: FIT PASS, SUPPORT UNKNOWN → BLOCKED for purchase conclusion
B: FIT PASS, SUPPORT PASS    → eligible for measurement

A 可以留在调查队列，但不能因为预期性价比高就越过 hard gate。

System Feasibility 也要单独建 Gate

  • 物理尺寸/slot/风道；
  • PSU 容量、连接器与线材方案；
  • PCIe lane/link 与主板限制；
  • host RAM / storage / OS；
  • 噪声、环境温度、持续负载；
  • 多卡时的互联与空间。

“GPU 本身 fit”不等于“你的机器能安全、稳定地部署它”。

Evidence Confidence

每个关键栏同时记状态与证据等级：

PASS / FAIL / UNKNOWN
+
DOCUMENTED / THIRD-PARTY / MEASURED-OWNED

例如 support = PASS 但只有一条旧论坛帖，和 support = PASS 且 exact runtime 官方矩阵 + 你的 preflight，风险完全不同。

决策终点必须是人工 Review，不是自动 BUY

课程可以自动淘汰明显不合格方案、计算预算、提醒价格带，但购买涉及卡况、资金、退货、市场变化与个人 utility。最终状态最多应到：

BLOCKED
→ ELIGIBLE-TO-MEASURE
→ EVIDENCE-SUFFICIENT-FOR-REVIEW
→ HUMAN DECISION

What this lesson does NOT prove

Gate 顺序不能保证你永远买到“最优硬件”，因为未来价格、软件和需求会变化。它的价值是让当时的选择可解释、可复查，并让 UNKNOWN 不会被漂亮的排行榜数字掩盖。

完成证据

完成本课后，保留一份 learner-owned completion artifact，至少包含：

  • 用自己的话画出或写出本节最小 mental model，并标出关键变量/资源层；
  • 完成本节小实验、worksheet 或无硬件 fallback；有真机时链接 raw Evidence，没有真机时明确标 L0 / DOCUMENTED / DEFERRED-HARDWARE；
  • 写一条绑定 Evidence 的 PASS / FAIL / UNKNOWN / BLOCKED 结论，说明它怎样影响本地 LLM 的容量、性能、兼容、成本或风险判断；
  • 写一句明确 non-claim：这份证据还不能证明什么。

只写“看完了”或抄规格表不算完成。课程要的是可复查的推理产物，而不是阅读打卡。
