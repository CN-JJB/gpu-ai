Slice 18 — NVIDIA、AMD、Apple、Intel 最后怎么变成“买不买”

前面已经学完四个生态。现在停止背架构，开始做决策。

1. 第一件事不是看显卡，是写 workload

model
quant
context
KV
concurrency
runtime
PP/TG goal

如果这些没写，所有“神卡推荐”都缺上下文。

2. 第一硬门槛：装得下吗？

单卡：

usable memory
>= weights + KV + workspace + headroom

多卡：

not sum(VRAM)
but per-device allocation + sharding

Apple：

not installed RAM
but safe unified working-set budget
装不下的候选，不参加性能排名。

3. 第二硬门槛：软件真的支持吗？

同一张卡至少要走完：

driver
→ runtime
→ backend
→ model format
→ kernels
→ correctness

把“支持”分成：

  • 官方当前支持；
  • 官方旧版本固定栈；
  • 社区 patch/build；
  • 只能枚举；
  • 不可用。

4. 然后才看性能屋顶

Decode

rough TG roof
≈ usable memory bandwidth
 / bytes streamed per token

Prefill

PP roof
≈ min(matrix compute × utilization,
      bandwidth × arithmetic intensity)

Multi-GPU

+ communication/link
+ synchronization
+ imbalance

5. 这时 architecture 才真正有用

架构不是答案，而是帮你解释 roof。

观察可能原因
PP 很快，TG 普通matrix compute 强，但 decode bandwidth roof 低
大显存但双卡 TG 慢capacity 赢，interconnect 输
新卡 Q4 没预期快backend 没走原生 low-bit matrix path
Mac 装得下但 TG 不高capacity roof 与 bandwidth roof 是两回事
AMD/Intel 理论强但实测弱软件/kernel maturity 可能是 roof

6. 买价只是 TCO 的一部分

card price
+ PSU
+ platform
+ cooling
+ electricity
+ expected repair
- resale

还有一个经常被忽略的成本：

driver / build / patch / maintenance time

7. 二手卡风险怎么进决策？

不是“矿卡不能买”，而是：

higher risk
→ require larger discount
→ require stronger testing evidence

高风险：

  • 改 BIOS；
  • 显存改装；
  • 板修；
  • 工程样品；
  • 腐蚀；
  • 内存错误；
  • 卖家拒测。

8. 证据也要打等级

等级例子
E3官方规格、当前 runtime docs、本机 raw benchmark
E2可复现社区测试、可靠技术媒体
E1单帖、卖家口述、无配置截图
E0未知

如果 TG 只靠 E1：

decision = NEEDS EVIDENCE

而不是脑补。

9. 为什么我不推荐一个万能 100 分评分表？

因为：

7B single-user
32B long-context
4-user server
hardware-learning lab

需要的是完全不同的权重。

正确流程：

hard gates
→ scenario
→ scenario-specific weights
→ decision

10. 最终输出不是“第一名”，而是行动

  • BUY
  • BUY IF PRICE ≤ X
  • KEEP CURRENT
  • SKIP
  • NEEDS EVIDENCE

11. 垃圾佬真正的核心能力

不是知道哪张卡最强

而是能把
硬件规格
+ 软件支持
+ workload
+ 实测
+ 二手风险
+ 成本
变成一个可解释决策

学生闭环 — 跨厂商硬件决策

硬件门槛：L0 主路径；真实硬件/市场只是增强。

成本：0 元教学路径。

风险：safe；涉及真实二手交易时课程只提供调查/验收方法，不替你自动购买。

能力目标

  • 把 fit、software support、performance roof、capacity、power/TCO 分成独立门槛
  • 用 hard gate 先淘汰不满足需求的候选，再比较软优势
  • 明确 UNKNOWN，不用游戏 FPS、品牌印象或单一 TOPS 替代 LLM 证据

小实验 / 反馈

做 Experiment 31：scenario hardware decision model；有真实候选机器/卡时做 Experiment 32：real candidate dossier。

Retrieval Practice

  1. 为什么“最便宜每 GB 显存”不是完整选卡规则？
  2. 如果某卡容量 PASS、software support UNKNOWN，你能把它排第一吗？
  3. 为什么 purchase price 和 TCO 必须分开？
  4. 同一张卡在不同 backend 下为什么可能从好选择变成坏选择？

完成证据

提交一个三候选 decision matrix：每个候选至少写 capacity / support / PP-TG roof / power-platform / price-risk，并为每个结论标记 PROVEN / ESTIMATED / UNKNOWN。

如何选择 / 迁移

以后换模型、换预算、换国家市场，只替换约束和证据；决策框架不变。
