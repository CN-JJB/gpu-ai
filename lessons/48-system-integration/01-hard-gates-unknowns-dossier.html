整机 System Integration — 为什么“综合 90 分”仍然可能不能买？

1. 现在把前 47 个 Slice 汇合

workload/model
+ GPU/VRAM
+ software
+ PCIe/topology
+ RAM
+ SSD
+ PSU/cables
+ cooling
+ serving/network
+ budget
→ machine decision

2. 不做万能综合分

假设：

速度 10/10
价格 10/10
显存 0/10

平均分看起来还能看。

但是目标模型装不下：

HARD GATE FAIL
→ REVISE
致命条件不能被其他优点平均掉。

3. 三类信息

HARD GATE
UNKNOWN BLOCKER
PREFERENCE

4. Hard Gate

例如目标：

runtime 需要 30 GiB
机器只有 24 GiB

结论：

REVISE

不是 24 GiB 卡“差”，是当前设计不满足当前目标。

5. UNKNOWN 和 FAIL 不一样

二手模组 PSU：

线长得能插
但不知道是不是这个 PSU 的原配/兼容线

不能写 PASS。

如果这是供电安全关键：

BLOCKED

6. Preference 最后才比较

TG
TTFT
J/token
noise
price
size
maintenance

这些只应该在可行方案之间排序。

7. 模型 Gate

不能只看：

GGUF 20GB
VRAM 24GB
→ fits

还要算：

weights
KV
context × concurrency
workspace/headroom
backend allocation

8. Software Gate

PCIe 能看到 GPU
!= CUDA/ROCm/Metal/SYCL backend 能稳定跑目标模型

必须有 runtime evidence。

9. 多卡 Gate

GPU0 pass
GPU1 pass
!=
2-GPU system pass

还要看：

split mode
PCIe topology
P2P
lane
interconnect
scaling

10. RAM / Storage

主机内存和 SSD 不是“GPU 之外不重要”。

RAM 不够
→ swap/OOM/load 问题

SSD 很慢
→ cold startup 可能很慢

但不要把 SSD 速度冒充 steady TG。

11. PSU/cable

总瓦数够
但 cable 不兼容
→ HARD FAIL

这正是为什么不能做单一分数。

12. Cooling

短测 55 tok/s：

10 分钟后 42 tok/s

如果你的目标是长期服务，sustained performance 本身就是容量。

13. Serving

单用户：

TG 很快

多人：

TTFT p95 爆炸

那它仍然可以失败你的 serving SLO。

14. 真正的 Dossier

每个 Gate
→ requirement
→ Evidence path/hash
→ PASS/FAIL/UNKNOWN

然后：

known FAIL → REVISE
critical UNKNOWN → BLOCKED
all gates pass → ACCEPT

15. ACCEPT 不等于“宇宙最强配置”

只意味着：

对这个 workload
按这套 evidence
当前设计可行

16. 最成熟的垃圾佬结论有时是

DO NOT BUY YET

因为缺了一条关键证据。

这不是没做完，是你终于没有拿真钱替未知数买单。

学生闭环 — Whole-Machine System Integration

硬件门槛：L0 模型/设计主路径；真机实验按页面对应 L1–L3。

成本：0 元教学主路径；不要求购买、拆修或高风险改造。

风险：默认 safe；涉及 PSU/硬件时只做只读调查与厂商手册约束下的正常安装，不做带电拆装。

能力目标

  • 把“GPU 很强”升级成整机层的容量、稳定、供电、散热和长期运行判断。
  • 把 PASS / FAIL / UNKNOWN 与具体 Evidence 对齐。
  • 知道什么情况下应该 BLOCKED 或 REVISE，而不是为了完成课程强行 ACCEPT。

小实验 / 反馈

做 Experiment 90：whole-machine feasibility model；真实目标做 Experiment 91：real machine dossier。

Retrieval Practice

  1. 为什么任何一个 hard gate FAIL 都不能被其他优点“平均掉”？
  2. critical UNKNOWN 为什么应该 BLOCKED，而不是乐观当 PASS？
  3. 一台机器模型能装下，但 PSU/散热/软件 support 未证明，你能 ACCEPT 吗？
  4. whole-machine dossier 与零件清单的根本区别是什么？

完成证据

完成一张 machine hard-gate matrix：模型容量、runtime support、性能/质量、host RAM/storage、PCIe、PSU、thermal、网络/服务、成本/风险；每项 PASS/FAIL/UNKNOWN 并链接 Evidence。

如何选择 / 迁移

换 GPU、模型或平台后，从 hard gates 重新算，不继承旧机器的 PASS；任何新未知都回到 evidence collection，而不是靠经验口头补齐。
