NVIDIA Architecture · 4/5 · L0→L2

NVIDIA 架构主线（四）：Ampere → Ada

这是本地 LLM 玩家最常遇到的 NVIDIA 世代区间之一。重点不是背 RTX 型号，而是理解：Ampere 如何继续扩大矩阵/低精度能力并分化消费与数据中心产品，Ada 又如何在能效、cache、图形/AI 专用资源上继续演化；真正买卡时则必须回到具体 SKU 的显存、带宽、功耗与软件支持。

Prerequisite Check

先能解释 Tensor Core 只是矩阵 datapath，且 token/s 可能受显存带宽而不是矩阵峰值限制。

真实问题：为什么 RTX 30/40 系“新一代更快”不能直接回答本地 LLM 买哪张？

本地 LLM 常先撞到显存容量 hard gate。一个更先进但显存更小的 SKU，可能根本放不下目标模型；一张较旧但 24 GB 的卡可能因为容量与带宽仍有独特价值。架构和 SKU 必须分开分析。

1. Ampere：矩阵路径继续扩大，但 family 内部分化非常重要

Ampere 同时覆盖消费 RTX 与数据中心加速器。它延续 Tensor Core 路线，并在不同产品上提供不同的数值、memory、互联和可靠性组合。学习 Ampere 最重要的不是把某个白皮书参数套到所有 GA10x/GA100 产品，而是养成“family → die → SKU”的层级意识。

结构化稀疏为什么是“条件式峰值”？

某些 Tensor Core 能在满足特定稀疏结构时跳过部分零值，从而提高有效吞吐。这里最重要的词是满足条件：

hardware supports sparse acceleration
+ model actually has required sparsity pattern
+ runtime/kernel uses sparse path
= possible acceleration

没有模型转换、稀疏模式和 kernel 支持，仅看到“sparse TOPS”并不能得到收益。

TF32 为什么值得理解？

TF32 可以把它理解成针对深度学习/HPC 某些场景设计的数值计算模式：它试图在 FP32 使用体验与 Tensor Core 吞吐之间取得折中。关键不是记 mantissa 位数，而是学会问：输入/累加语义是什么？软件库默认是否启用？目标推理 workload 是否真的走这条路径？

2. 消费 Ampere 为什么在“二手 LLM”里存在特殊地位？

不是因为“30 系最好”，而是历史市场形成了一些大显存、高带宽、成熟 CUDA 生态的 SKU。对于本地模型，容量可以把候选集合直接切开：

model + KV + runtime buffers > VRAM
→ 纯显存路径不成立
→ 必须降量化 / 降上下文 / 部分 offload / 多 GPU / 换卡

因此 24 GB 与 12 GB 的差异可能比同代核心数量差异更决定“能不能跑”。这也是为什么课程始终把 fit 放在 benchmark 前。

3. Ada：更高能效、更大的缓存思路与新一代专用单元

Ada 继续提升每瓦性能，并显著强化片上 cache 等数据路径设计。对 LLM 的直接价值要按 workload 判断：cache 能减少部分外部 DRAM 流量，但如果模型工作集远大于 cache、每 token 仍需流式读取大量权重，显存带宽仍可能是主导上限。

大 cache 什么时候有帮助？

  • 热点数据能重复命中；
  • working set 的一部分具有明显局部性；
  • 减少 metadata / activation /重复访问的 DRAM 流量。

什么时候不能神化？当 workload 本质上需要持续读取远大于 cache 的独特权重字节时，cache 不会把 DRAM 需求变没。

4. Ampere vs Ada：把“代际”拆成五张表

表要记录
ComputeSM 组织、general FP/INT、Tensor numeric modes
MemoryVRAM、bus、bandwidth、cache
Fit模型权重、KV、runtime buffer 是否能放下
SystemTGP、连接器、散热、机箱、PSU
Softwaredriver/runtime/backend/current model-format support

只有把五张表放在一起，才有资格谈“这代更适合我的本地 LLM”。

Worked Example：24 GB Ampere vs 16 GB Ada

假设目标模型在某量化下连同合理 KV/buffer 需要约 19 GB 可用显存。此时：

  • 24 GB 卡首先通过 capacity hard gate；
  • 16 GB 卡即使每瓦性能更高，也需要降低模型/上下文或 offload；
  • 若目标换成 8B、总工作集只有约 7 GB，capacity 差异不再是 hard gate，此时 Ada 的能效、kernel、价格才更有可能主导。

这不是推荐某张卡，而是展示约束顺序：先能不能做，再比较做得多快/多省。

5. PCIe 代际不是显存带宽

初学者常把 PCIe bandwidth 与 VRAM bandwidth 混在一起。前者连接 host 与 GPU，后者连接 GPU 与本地显存。模型完全驻留显存并持续 decode 时，最常见的权重流量发生在 GPU↔VRAM；只有发生 host/device transfer、offload、多设备通信时，PCIe 才可能成为更明显瓶颈。

Why it matters

  • Ampere/Ada 是大量现实候选卡所在世代，架构知识必须能落到 SKU。
  • 大显存可以是 hard gate，而架构代际通常是 soft tradeoff。
  • Tensor/sparse/TF32 等峰值都有明确条件，不能当通用 LLM 分数。
  • cache、VRAM bandwidth、PCIe 是不同数据路径。
  • 能效会影响长期电费、噪声、热稳态和 PSU/机箱设计。

常见误区

  • “40 系一定比 30 系适合 LLM”——忽略容量、带宽和价格。
  • “PCIe 4.0 x16 很快，所以显存也很快”——两条不同链路。
  • “Sparse TOPS 可以直接算 token/s”——前提通常不成立。
  • “大 L2 等于不吃显存带宽”——working set 与访问模式决定实际命中。
  • “同为 Ampere 就有相同 Tensor/FP64/HBM 能力”——数据中心/消费 SKU 分化。

小实验：做一张真实候选卡约束表

不需要购买。选择两个具体 SKU（最好一个 Ampere、一个 Ada），记录 exact VRAM、官方 memory bandwidth、TGP、physical form factor、当前目标 runtime support。再用一份假设模型预算做 fit 判断。

预期观察：你会发现“architecture 更先进”并不能覆盖所有 hard gates，且不同 workload 会改变排序。

排错

  • 显存明明够却 OOM：检查 runtime buffer、KV、context、并发 slot、driver reservation。
  • 新卡比预期慢：确认 GPU offload、backend、quant kernel、power/thermal、batch/workload。
  • PCIe utilization 高：检查是否发生部分 offload/频繁 host transfer，而不是先怪 VRAM bandwidth。

  5. 为什么 24 GB 较旧卡可能对某模型比 16 GB 新卡更实用？什么时候这个结论会反过来？

Decision Rule

先做 fit hard gate，再比较 memory/compute/software/system/cost。任何“新一代一定更值”“AI TOPS 更高一定更快”的结论都不合格；必须落到 exact SKU + exact model/runtime/workload。
