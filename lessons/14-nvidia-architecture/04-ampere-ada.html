NVIDIA 架构 4 — Ampere → Ada：现代 LLM kernel 的直接祖先

1. Ampere 先解决的是“怎么让数据及时到 Tensor Core”

矩阵算力越来越高以后，新问题变成：

Tensor Core can consume data very fast
but
global memory is far away

所以 kernel 需要 pipeline：

tile 0 compute
while
tile 1 load
while
tile 2 address/schedule

2. Async global → shared copy

Ampere 加入硬件支持，让数据从 global memory 异步搬到 shared memory，并减少普通 register staging。

old:
global → register → shared

Ampere async path:
global ───────────→ shared
          while compute continues

这正是现代 CUTLASS / fused GEMM / attention pipeline 的核心原语之一。

3. Split arrive/wait barrier

生产者和消费者不必每一步都做一个全 block 的粗 barrier。

可以表达：

producer: tile ready
consumer: wait tile
→ compute
producer: prepare next tile

4. Third-generation Tensor Core：precision 成为架构设计中心

  • FP16；
  • BF16；
  • TF32；
  • INT8/INT4；
  • 相关 structured sparsity path；
  • FP64 Tensor Core（特定 compute products）。

TF32 再提醒一次

FP32 storage
→ Tensor Core converts multiply input precision
→ FP32 accumulation

它不是一种“把模型保存成 TF32”的文件格式。

5. Ampere 不是一个统一 SM

GA100（cc 8.0）和 GA10x（cc 8.6）有明显差异。

官方 tuning guide 特别指出 8.6 每 SM 每周期 FP32 operation capacity 与 8.0 不同。

第五次重要抽象：从 Pascal 开始，必须把“架构 family”和“compute capability / die variant”同时看。

6. A100 的大 L2 / residency control

GA100 把 L2 capacity 大幅提高，并允许 programmer 提示 persistence。

核心思想：

if data reuse can hit L2
→ less HBM traffic
→ higher effective arithmetic intensity

7. Ada：把重点转向 cache、效率和 RTX AI

Fourth-generation Tensor Cores

Ada 进入 FP8-era 的 RTX inference 路径。

AD102 的 96 MB L2

NVIDIA whitepaper 给出的 full AD102 L2 为 96 MB，相比 GA102 6 MB 是巨大跃升。

为什么消费者 GPU 要这么大 L2？

GDDR traffic expensive
+
graphics / ray tracing / compute working sets
benefit from locality
→ larger last-level cache

对本地 LLM：

  • 权重 streaming 通常仍大于 cache；
  • 但 metadata、小 tensor、重复访问仍可能受益；
  • 不能把 96 MB L2 当成“额外 VRAM”。

SER

Shader Execution Reordering 是 Ada 的重要 graphics feature，但不要硬说它会提升 llama.cpp token/s。

可迁移的概念只有：

irregular/divergent work
can sometimes be regrouped
to restore execution coherence

AV1

Ada 的 NVENC 增加 AV1 encode。对于 multimodal/creator workstation 很实用，但不是 LLM core compute。

8. Ampere/Ada 对本地 LLM 的真正判断

featureLLM relevance
Tensor precision高：backend/kernel 能否映射低精度 GEMM
memory bandwidth高：decode weight streaming
VRAM高：模型/KV capacity
async copy/shared pipeline高：现代 fused kernel
large L2中：取决于 reuse pattern
SER/RT对纯 LLM 低
AV1多媒体/多模态系统有用

学生闭环 — Ampere / Ada

硬件门槛：L0；真机增强 L1/L2（任意 NVIDIA GPU 均可做 capability inventory）。

成本：0 元主路径；不要求为历史架构买卡。

风险：safe；只读资料、设备信息与 benchmark。

替代路径：没有对应年代 GPU 也能完成 Experiment 23；有 NVIDIA 卡才做 Experiment 24。

能力目标

  • 从“上一代瓶颈 → 本代机制 → 今天 LLM 的影响”解释本页，而不是背型号。
  • 把 architecture family 与具体 SKU 的显存、带宽、互联、precision、功耗和软件生命周期分开。
  • 识别哪些是稳定架构事实，哪些必须在当前 driver/runtime 上重新验证。

小实验 / 反馈

做 Experiment 23：NVIDIA generation feature traps。如果手里有 NVIDIA 卡，再做 Experiment 24：real NVIDIA capability inventory。

Retrieval Practice

  1. 更大的 cache、异步数据搬运、Tensor precision 与消费/数据中心分支如何改变实际瓶颈？
  2. 为什么 Ampere/Ada 的 Tensor 峰值不能直接预测 llama.cpp TG？
  3. 如果一张旧 NVIDIA 卡理论算力不错，但最新 runtime 不再支持，你的结论属于“架构能力”还是“当前可用性”？
  4. 为什么“同一 architecture”也必须继续查 memory system、SKU cut-down、power 和 software support？

完成证据

做一张 Ampere / Ada 代际卡片：前代瓶颈 / 本代改变 / LLM 影响 / 二手价值可能受什么影响 / 当前软件支持仍需查什么。禁止写“某代一定更值”。
