NVIDIA 架构主线（三）：Volta → Turing

从这一段开始，现代 AI GPU 的轮廓真正清晰：通用 CUDA 路径继续演化，同时加入专门的矩阵数据通路；图形产品又加入 RT 路径。理解这里，你才能正确阅读“Tensor Core”“混合精度”“INT8/INT4”“AI TOPS”这些后来被大量营销化的词。

Prerequisite Check

你应能区分“数据格式”“理论吞吐”“应用是否有 kernel 命中”。如果不确定，回看 Maxwell/Pascal 的低精度部分。

真实问题：为什么 CUDA Core 很强还要另外做 Tensor Core？

矩阵乘法由大量规则的乘加组成。通用执行资源能做，但如果一个 workload 长期、海量地重复同一种局部结构，就值得设计专门 datapath，用更少控制开销和更高数据复用完成更多乘加。

核心原则：Tensor Core 不是“另一块 GPU”，而是 SM 内针对矩阵乘加热点设计的专用执行路径。GPU 仍需要通用核心处理控制、非矩阵操作、地址计算、归约和大量辅助工作。

1. Volta：Tensor Core 把混合精度矩阵计算变成一等公民

Volta 的突破是把 Tensor Core 作为明确的矩阵乘加资源加入 SM。学习时不要死背某个 tile 尺寸，而要理解数据流：

lower-precision inputs
        ↓
matrix multiply-accumulate datapath
        ↓
higher/appropriate accumulator
        ↓
result

所谓“混合精度”不是一句“FP16 比 FP32 快”，而是输入、乘法、累加和输出可能使用不同格式，以速度、范围、精度和稳定性做折中。

为什么累加格式值得单独看？

大量小误差在长归约中会累积。即使乘法输入较低精度，使用更高精度或更大动态范围的 accumulator 也可能显著改善数值行为。因此硬件规格里“支持某 dtype”远远不够，你还要知道计算模式。

2. Volta 的 Independent Thread Scheduling：SIMT 不是永远锁步的简单机器

现代 SIMT 的线程控制比“32 个线程永远做完全相同事情”复杂。Volta 改进线程调度语义，使 warp 内线程在控制流与同步上有更细粒度能力。对学生最重要的结论不是去写 tricky warp code，而是：

  • 不要把 warp 当作不可分割的单线程；
  • 也不要假设传统隐式 lockstep 行为永远安全；
  • warp-level algorithm 应使用明确的同步/协作原语。

3. Turing：把 Tensor Core 带到更广的产品，同时扩展整数/低精度路线

Turing 让 Tensor Core 与 RT Core 一起进入新的消费图形架构语境。对本地 LLM 而言，RT Core 不是核心关注点，重要的是矩阵/低精度能力继续扩展。

INT8 / INT4 为什么值得注意但不能直接等同 LLM 量化？

“硬件支持 INT4”与“某个 GGUF Q4 模型能高效运行”之间隔着很多层：

model quantization format
→ packed weight layout
→ dequant / scale scheme
→ kernel implementation
→ hardware instruction path
→ runtime/backend dispatch

因此看到规格表的 INT4 TOPS，不能直接拿来预测 llama.cpp 某个量化的 token/s。

4. CUDA Core 路径也在演化：专用单元没有取代通用计算

Turing 等架构仍然持续优化通用整数/浮点、调度、cache/shared 组织。真实 LLM inference 是多个 kernel 和阶段组成的程序，不会永远待在 Tensor Core 上。

工作可能更依赖
大矩阵乘法Tensor/matrix path + memory
layernorm/RMSNormvector/reduction/general CUDA
samplinggeneral compute + memory + CPU interaction
tokenization常主要在 CPU/host
KV movementmemory system

Worked Example：为什么“Tensor Core 世代”仍可能 decode 不快？

设模型已经量化并完全放入显存。生成一个 token 时，如果每层都要从显存读取大量权重，而可并行 batch 很小，那么内存流量可能比矩阵单元峰值更先到上限。

粗略思路：

每 token 需要读取的有效权重字节 ≈ B
显存可持续带宽 ≈ BW
理想 memory roof ≈ BW / B token/s

这不是完整性能公式，但它解释了：即使 Tensor Core 峰值暴涨，decode 的实际 token/s 也可能主要被 bandwidth roof 限制。后续 bandwidth/roofline 课会正式展开。

5. RT Core 为什么仍值得知道？

不是为了 LLM，而是为了学会识别“同一 GPU 上的专用单元”。RT Core 针对光追几何工作；Tensor Core 针对矩阵工作。它们提醒你：营销中的“AI/RT/Shader 性能”属于不同数据路径，不能混成一个总分。

Why it matters

  • Volta 是理解现代 Tensor Core/mixed precision 的起点。
  • Turing 让你学会把“硬件低精度能力”和“具体模型量化 backend”分层。
  • decode 的 memory-bound 特性提醒你：矩阵峰值不是唯一上限。
  • 专用单元 coexistence 训练你阅读复杂 GPU 方框图，而不是把所有 TOPS 加在一起。
  • 旧 Tesla/Turing 二手卡的现实价值还取决于显存、功耗、driver、runtime、kernel 与价格。

常见误区

  • “Tensor Core 就是专门跑神经网络的万能核心”——它更准确地说是矩阵计算 datapath。
  • “INT4 TOPS 高，所以 Q4 GGUF 一定飞快”——格式和 kernel 路径可能完全不同。
  • “有 Tensor Core 就不再需要 CUDA Core”——大量辅助/非矩阵工作仍依赖通用资源。
  • “AI 峰值比上一代高 2 倍，token/s 就高 2 倍”——memory/launch/shape/batch 均可改变瓶颈。

小实验与预期观察

在 generation feature trap 表中新加四列：matrix unit、supported numeric modes（仅记录可靠来源明确宣称的）、memory bandwidth、current runtime/backend status。选一张 Pascal 与一张 Turing 卡比较。你应该观察到“新增 Tensor Core”只是能力矩阵中的一列，不足以单独决定购买。

无硬件路径

本节 L0 可完全通过架构图、产品规格和课程 worksheet 完成。不要为了验证 Tensor Core 买老卡。真机 L1 只做安全的 capability/benchmark inventory，不做超压。

排错

  • benchmark 看不到 Tensor Core 利用：确认数据类型、矩阵 shape、library/kernel 与实际 dispatch。
  • 量化模型速度异常：检查是否发生 CPU fallback、部分 layer offload、unsupported quant kernel。
  • 理论带宽很高但吞吐低：检查实际 memory clocks、power/thermal、数据复用、host transfer 和 batch/shape。

Retrieval Practice

  1. 为什么专门矩阵 datapath 在统一可编程 GPU 之后仍然合理？
  2. 混合精度里为什么要区分 input、multiply、accumulate、output？
  3. 为什么硬件 INT4 支持不能直接证明 GGUF Q4 性能？
  4. 给出一个 Tensor Core 很强但 decode 仍 memory-bound 的解释。
  5. RT Core 的存在如何帮助你理解“同一 GPU 有多类互不等价的峰值指标”？
  6. 如果 Turing 二手卡价格便宜，哪些当前软件事实仍必须重新验证？

Decision Rule

可以把 Volta/Turing 的 Tensor Core 当成“可被特定 kernel 利用的矩阵上限”；不能把 AI TOPS 或某种低精度峰值直接换算成模型 token/s。购买和优化必须证明目标 runtime + model format + kernel 真的命中该路径。
