NVIDIA 架构 2 — Maxwell → Pascal

这两代最重要的课不是“工艺进步”，而是：更聪明的 SM partition，以及同一 architecture family 可以出现完全不同的产品路线。

1. Maxwell：Kepler 的问题不是算力不够，而是太难喂

Kepler SMX 很宽。Maxwell 的设计目标转向执行效率。

SMM 的四个 partition

Maxwell 仍有四个 warp scheduler，但和 Kepler 不同的是，每个 scheduler 的功能单元更明确地属于自己的 partition。

SMM
├─ scheduler 0 → dedicated CUDA-core group / units
├─ scheduler 1 → dedicated CUDA-core group / units
├─ scheduler 2 → dedicated CUDA-core group / units
└─ scheduler 3 → dedicated CUDA-core group / units

这种 power-of-two、warp-width-friendly 的映射简化 scheduling，减少 stall。

重要：Maxwell 每 SM CUDA core 数比 Kepler 少，不代表倒退。它在用更高 execution efficiency换更好的 perf/area/perf/W。

2. Maxwell 的 memory hierarchy 也重新整理

Fermi/Kepler：

one on-chip pool
→ choose L1/shared split

Maxwell：

dedicated shared memory
+
unified L1/texture function

这样 shared-memory-heavy kernel 不再和 L1 用同样方式争那块物理容量。

更多 resident blocks

每 SM 最大 active blocks 从 16 提到 32，对小 thread-block kernel 特别有帮助。

Native shared atomics

histogram/local accumulation 这类 shared-memory contention workload 得到更直接的硬件支持。

3. Pascal：第一次必须认真区分“GP100”和“GP10x”

如果只写：

Pascal = HBM2 + NVLink + fast FP16

这节课就是错的。

4. GP100：HPC / training 分支

更小的 compute-oriented SM

GP100 SM 有 64 FP32 cores，继续 Maxwell 的“不要盲目做超宽 SM”方向。

HBM2

GP100 通过超宽 HBM2 interface 提高 capacity/bandwidth efficiency。

NVLink

支持平台可以使用 NVLink 提高 GPU↔GPU / GPU↔CPU 互联能力。

这正是 Slice 11 的历史来源之一。

FP16

GP100 的 FP16 half2 路径专门面向 training/low-precision compute，FP16 throughput 可以高于 FP32。

5. GP104/GP10x：另一个 Pascal

消费/graphics-oriented Pascal 的 FP16 路径和 GP100 完全不同。官方文档甚至明确给出：GP104 的 FP16 arithmetic throughput 远低于 GP100。

但 GP104 等变体加入了 DP4A 这类 INT8 dot-product 指令：

4 × int8 products
→ accumulate int32

这对 inference 很有意义。

第三次重要抽象：“architecture name”已经不足以预测 AI 能力。必须看 exact die / product variant。

6. Pascal Unified Memory：从“托管分配”走向 page fault

Pascal 增加 GPU page fault 和更大的 unified virtual addressing 能力。

GPU touches non-resident managed page
→ page fault
→ runtime migrates/maps page
→ execution continues

这使 heterogeneous memory 更灵活，但 page migration 仍有成本。它不是“CPU RAM 和 VRAM 自动一样快”。

7. 对垃圾佬最重要的 Pascal 教训

看到 Pascal你还必须问
FP16?GP100 还是 GP10x？
HBM2?具体卡是不是 GP100/HBM 产品？
NVLink?具体 SKU/board 是否有？
INT8?具体 die / backend 是否使用 DP4A？
今天还能不能跑？看当前 driver/CUDA/backend support intelligence

8. LLM 迁移

Pascal 没有 Tensor Core，但这不等于“完全不能推理”。对于 memory-bound quantized decode，VRAM bandwidth、capacity 和 backend kernel 仍可能比 Tensor TOPS 更直接。

但今天买旧 Pascal 的软件寿命问题，必须和架构能力一起算 TCO。
