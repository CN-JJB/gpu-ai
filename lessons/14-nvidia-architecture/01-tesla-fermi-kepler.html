NVIDIA 架构 1 — Tesla / G80 → Fermi → Kepler

这一节不是古董考古。今天 CUDA kernel 里最基本的 thread、warp、SM、shared memory、latency hiding，都从这一阶段长出来。

1. Tesla/G80：真正的起点是“统一”

更早的 GPU 为不同图形阶段准备不同执行资源。问题是：像素很多时，vertex 单元不能自动变成 pixel 单元。

old:
vertex hardware | pixel hardware | other fixed stages

Tesla/G80:
one programmable processor pool
→ graphics shader work
→ compute work

这就是 unified architecture 的关键。

第一次重要抽象：GPU 不再只是一条固定图形流水线，而是一台由大量轻量线程驱动的 throughput computer。

CUDA 带来的编程模型

grid
  └─ thread block
      └─ threads

hardware:
GPU
  └─ SM
      └─ warps

shared memory 和 barrier 让同一个 block 的线程能做低延迟协作。这套基本结构一直延续到今天。

2. 为什么光有“很多线程”还不够？

第一代 CUDA GPU 很擅长规则、高并行工作，但科学计算很快暴露问题：

  • 不规则 global-memory access 很贵；
  • 缺少成熟 cache hierarchy；
  • FP64 / IEEE 行为要更强；
  • HPC 需要 ECC；
  • 多个 kernel/transfer 要更好重叠。

3. Fermi：把 GPU 当作 compute processor 重新设计

Cache hierarchy

SM
├─ shared memory
├─ L1
└─ ...
      ↓
shared L2
      ↓
DRAM

Fermi 加入真正面向 general-purpose compute 的 L1/L2 hierarchy。L1 和 shared memory 共用一块可配置 on-chip storage，而 L2 服务整个 GPU。

为什么 cache 对 GPGPU 重要？

shared memory 要程序员自己安排；cache 可以接住程序无法完全显式管理的：

  • irregular reuse；
  • register spill；
  • 跨 SM 数据复用；
  • 复杂指针访问。

HPC 语义也变强

Fermi 带来更成熟的 FP64/FMA、64-bit addressing、ECC、concurrent kernels 等。

第二次重要抽象：GPU compute 从“你必须手动照顾所有数据”走向“显式 shared memory + 硬件 cache”共同工作。

4. Kepler：更宽的 SMX 需要更多“可调度的独立工作”

Kepler SMX 堆进更多 execution resources。硬件更宽以后，新问题出现：

更多执行槽
≠ 自动更多性能

如果没有 enough:
- active warps
- independent instructions
- thread blocks

execution slots still idle

TLP + ILP

Kepler tuning guide 特别强调两种并行：

  • TLP：更多 warp/thread；
  • ILP：同一线程/warp 中更多独立 instruction。

这就是为什么“occupancy 100%”也不是唯一答案：有些 kernel 可以用更强 ILP 补偿 warp 数。

Warp Shuffle

Kepler 引入 warp shuffle，lane 之间可以直接交换 register value：

old reduction:
register → shared → sync → shared → register

shuffle:
register lane A ↔ register lane B

它减少了某些 warp-local 算法对 shared memory 的依赖，是现代 reduction / softmax kernel 的祖先之一。

Hyper-Q

在 GK110 上，Hyper-Q 增加独立工作队列，减少多个 CUDA stream / process 被一个窄 host queue 人为串行化的问题。

Dynamic Parallelism

GK110 允许 GPU kernel 再 launch kernel。

CPU launch parent
        ↓
GPU parent kernel
        ↓
GPU launches child grid

它提高表达能力，但不是“GPU 自己 launch 就一定快”。launch overhead、work granularity 仍需测。

5. 不要把 Kepler 当成一张芯片

GK104 与 GK110 的目标/功能并不一样。Hyper-Q、Dynamic Parallelism 等关键 feature 需要具体到相应 variant。

6. 三代真正留下来的东西

代留下来的核心观念
Teslaunified programmable GPU + SIMT
Fermicompute cache hierarchy + reliability + concurrency
Keplerwide SM needs TLP/ILP; warp-level communication; more work queues

7. 和今天 LLM kernel 的连接

warp shuffle
→ reduction / softmax

shared memory
→ GEMM tile / attention tile

many active warps
→ latency hiding

cache hierarchy
→ irregular metadata / KV / weight reuse

你学的不是古董型号，而是现代 kernel 设计语言的来源。

学生闭环 — Tesla / Fermi / Kepler

硬件门槛：L0；真机增强 L1/L2（任意 NVIDIA GPU 均可做 capability inventory）。

成本：0 元主路径；不要求为历史架构买卡。

风险：safe；只读资料、设备信息与 benchmark。

替代路径：没有对应年代 GPU 也能完成 Experiment 23；有 NVIDIA 卡才做 Experiment 24。

能力目标

  • 从“上一代瓶颈 → 本代机制 → 今天 LLM 的影响”解释本页，而不是背型号。
  • 把 architecture family 与具体 SKU 的显存、带宽、互联、precision、功耗和软件生命周期分开。
  • 识别哪些是稳定架构事实，哪些必须在当前 driver/runtime 上重新验证。

小实验 / 反馈

做 Experiment 23：NVIDIA generation feature traps。如果手里有 NVIDIA 卡，再做 Experiment 24：real NVIDIA capability inventory。

Retrieval Practice

  1. 为什么 unified programmable GPU、cache/ECC/compute capability 与早期 GPGPU 生态比“核心数量”更重要？
  2. Tesla→Fermi→Kepler 中，哪一次变化最直接改变你今天读旧卡资料的方法？
  3. 如果一张旧 NVIDIA 卡理论算力不错，但最新 runtime 不再支持，你的结论属于“架构能力”还是“当前可用性”？
  4. 为什么“同一 architecture”也必须继续查 memory system、SKU cut-down、power 和 software support？

完成证据

做一张 Tesla / Fermi / Kepler 代际卡片：前代瓶颈 / 本代改变 / LLM 影响 / 二手价值可能受什么影响 / 当前软件支持仍需查什么。禁止写“某代一定更值”。
