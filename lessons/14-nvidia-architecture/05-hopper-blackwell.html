NVIDIA 架构 5 — Hopper → Blackwell：Transformer 开始反过来塑造 GPU

1. 先纠正产品线直觉

Ampere
├─ datacenter
└─ consumer

2022:
Hopper → mainly datacenter
Ada    → RTX / workstation / inference products

所以不能画成：

Ampere → Hopper → Ada

它们是部分并行的市场分支。

2. Hopper：数据搬运本身变成专用硬件

Ampere 已经有 async global→shared。

但线程还需要参与很多 address generation / copy orchestration。

TMA — Tensor Memory Accelerator

tensor coordinates + descriptor
→ TMA hardware
→ large multidimensional global↔shared transfer

发起 copy 的线程很少，其他线程可以继续算。

最重要的 Hopper 观念：当 Tensor Core 足够快，喂数据本身值得做成 accelerator。

3. Thread Block Cluster

传统 CUDA locality：

thread block
→ scheduled on one SM
→ shared memory local to that block/SM

Hopper 增加 cluster：

multiple blocks
→ co-scheduled nearby SMs
→ hardware-assisted cooperation

Distributed Shared Memory

cluster 内 block 可以访问其他 block 的 shared-memory region，建立更大的 cooperative locality。

4. FP8 + Transformer Engine

Hopper 第四代 Tensor Core 支持 FP8，并加入 Transformer Engine 去管理 transformer layer 的 scaling/precision。

这代表 AI accelerator 从：

"support low precision"

进一步变成：

"manage when/how to use low precision"

5. 为什么这些设计和 FlashAttention / modern GEMM 很像？

因为软件和硬件在向同一个方向收敛：

producer warp
→ move tile

consumer warp
→ MMA

async barriers
→ overlap stages

larger cooperative scope
→ reuse across more work

6. Blackwell：先分 datacenter 和 RTX

Blackwell 是一个 architecture family，不是一个固定 package。

Datacenter Blackwell

重点在：

  • large-scale transformer；
  • HBM / scale-up interconnect；
  • 第二代 Transformer Engine；
  • 更低 precision；
  • 部分旗舰产品采用 multi-die/package 设计。

RTX Blackwell

NVIDIA RTX Blackwell whitepaper显示：

  • 5th Generation Tensor Cores；
  • FP4 support；
  • 128 KB L1 Data Cache / Shared Memory in documented SM；
  • GDDR7 generation；
  • 4th Generation RT Core。

RTX Blackwell 不能因为名字相同就被当成 B200/GB200 的小号：

same architecture lineage
!= same die topology
!= same memory system
!= same interconnect

7. FP4 对 LLM 是什么机会？

理论上：

FP16 → FP4
can reduce:
- storage
- memory traffic
and increase:
- native matrix throughput

但是 Slice 13 的四层模型仍然成立：

model file quant
→ packed representation
→ runtime kernel
→ matrix instruction
→ accumulator
千万别写：“RTX 50 支持 FP4，所以任何 Q4_K_M GGUF 都自动跑 FP4 Tensor Core。”这在格式和 kernel 层面没有逻辑必然性。

8. 从 Tesla 到 Blackwell，主线其实只有三条

Execution

unified shader
→ wider SM
→ partitioned SM
→ specialized FP/INT
→ matrix units
→ warp specialization / cluster

Memory/data movement

explicit DRAM/shared
→ L1/L2
→ larger caches
→ async copy
→ TMA / cluster locality

Numerics

FP32/FP64
→ FP16/INT8
→ Tensor FP16
→ INT8/INT4
→ BF16/TF32
→ FP8
→ FP4

9. 最终买卡公式

architecture capability
× exact SKU implementation
× software support
× workload bottleneck
× price / power / risk
= real value

少任何一项，都不能从 architecture 名字直接推导“垃圾佬神卡”。

学生闭环 — Hopper / Blackwell

硬件门槛：L0；真机增强 L1/L2（任意 NVIDIA GPU 均可做 capability inventory）。

成本：0 元主路径；不要求为历史架构买卡。

风险：safe；只读资料、设备信息与 benchmark。

替代路径：没有对应年代 GPU 也能完成 Experiment 23；有 NVIDIA 卡才做 Experiment 24。

能力目标

  • 从“上一代瓶颈 → 本代机制 → 今天 LLM 的影响”解释本页，而不是背型号。
  • 把 architecture family 与具体 SKU 的显存、带宽、互联、precision、功耗和软件生命周期分开。
  • 识别哪些是稳定架构事实，哪些必须在当前 driver/runtime 上重新验证。

小实验 / 反馈

做 Experiment 23：NVIDIA generation feature traps。如果手里有 NVIDIA 卡，再做 Experiment 24：real NVIDIA capability inventory。

Retrieval Practice

  1. TMA、cluster、Transformer Engine、FP8/FP4 为什么说明“喂数据与管理精度”本身已成为硬件设计对象？
  2. 为什么 RTX Blackwell 不能被当作 B200/GB200 的缩小版？
  3. 如果一张旧 NVIDIA 卡理论算力不错，但最新 runtime 不再支持，你的结论属于“架构能力”还是“当前可用性”？
  4. 为什么“同一 architecture”也必须继续查 memory system、SKU cut-down、power 和 software support？

完成证据

做一张 Hopper / Blackwell 代际卡片：前代瓶颈 / 本代改变 / LLM 影响 / 二手价值可能受什么影响 / 当前软件支持仍需查什么。禁止写“某代一定更值”。
