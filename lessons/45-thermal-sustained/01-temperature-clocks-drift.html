Thermal / Cooling — 为什么冷机 55 tok/s，十分钟后只剩 43？

Prerequisite Check

开始前，你应该能同时观察 throughput、temperature、clock 与 power，并理解短时间 benchmark 只能描述一个瞬时热状态，不能自动代表长时间稳态性能。

如果还不熟：先把测试分成 warm-up、steady window 和 cooldown 三段。任何“热降频”结论都应建立在同一 workload 下随时间变化的性能与遥测证据上，而不是凭风扇声音或单个温度点判断。

真实问题

一张二手 GPU 刚启动时 benchmark 很漂亮，但持续生成十几分钟后 tok/s 明显下降。原因可能是温度限制、功率限制、时钟变化、机箱风道，甚至 workload 自身发生变化。

真正的问题是：这张卡能否在你真正需要的持续运行窗口里保持可接受的 clocks、temperature、errors 与 throughput，而不是只在冷机的几十秒里表现好？二手验收和长期部署都必须看 sustained behavior。

1. 短跑和长跑不是一个硬件状态

workload starts
→ cooler still cool
→ clocks boost
→ heat accumulates
→ equilibrium
30 秒冷机跑分不能自动代表 30 分钟 sustained TG。

2. Temperature 不是唯一答案

温度由很多东西共同决定：

board power
ambient
heatsink
fan
case airflow
neighbor GPU
dust
form factor

3. 不要背一个万能 80°C

不同 GPU 有：

edge/core
hotspot/junction
memory temperature
different target/max

所以：

80°C = throttle

不是通用规则。

4. Clock 掉了也不一定是散热

NVIDIA 当前 clock-event reason 里就区分：

power cap
thermal slowdown
power brake
other limits

所以：

clock ↓

只能先说“发生了降频/状态变化”。

5. Synthetic thermal drift

time:   0 → 240s
temp:  55 → 86°C
clock:1900 →1450 MHz
TG:    55 → 42 tok/s

TG：

42 / 55
≈ 0.764

也就是约：

-23.6%

温升 + clock 下降 + TG 下降，thermal/power management 变得很可疑。

6. 但还不能直接判 exact cause

最好再看：

thermal event reason?
power cap?
power brake?
hotspot/memory temp?

7. Hot-but-stable case

temp 80 → 84°C
clock 1800 → 1790
TG 50 → 49.8

性能基本没掉。

所以：

温度高
!=
正在 throttle

8. Ambient 很重要

20°C room
vs
32°C room

同一张二手卡都可能完全不同。

买卡/换散热器对比要记 ambient。

9. Open bench 也会骗人

桌面裸奔：

fresh air everywhere

塞进机箱双卡：

GPU0 exhaust
→ GPU1 intake
→ recirculation

垃圾佬多卡尤其明显。

10. Fan / noise 是另一个目标

最低温度不一定是最好系统。

more fan
→ lower temp
→ more noise

真实目标可能是：

sustained tok/s
subject to
temperature + noise

所以可以比较：

vs

会影响前几个样本。

13. 实验默认不调功耗墙

先只读测：

TG

clock

不默认做：

完成证据

教材补全：热设计的目标是“稳态性能”，不是最低温度

建立稳态视角

cold boost
→ heat accumulation
→ fan response
→ power/thermal equilibrium
→ sustained throughput

垃圾佬最容易犯的错误，是拿卖家 20 秒截图、开盖裸机跑分，推导机箱内 30 分钟双卡服务表现。

0–30 s TG20 min TG噪声
Card A5554中
Card B5643高

如果目标是 24/7 服务，A 的实际容量反而更高。

不要只测 core temperature

视硬件可用 telemetry，还应关注 hotspot/junction、memory temperature、clock、board power 与 limiter/event reason。某个传感器不支持时写 N/A，不要猜。

slot spacing
airflow direction
neighbor heat
riser/layout
ambient
fan curve

单卡裸奔通过，不等于整机热设计通过。

安全边界

课程默认只做正常负载、只读 telemetry 与厂商允许的普通设置。不开盖带电操作，不用极端 power/voltage 设置来“证明稳定”。

Troubleshooting：持续性能下降时怎么区分热、功率和 workload？

  1. 先确认 workload 没变：固定模型、量化、prompt/output 长度、batch/concurrency 与 runtime 参数。
  2. 对齐时间线：同时记录 tok/s、temperature、clock、power 与错误信号，观察性能下降发生在谁之前、谁之后。
  3. 温度升高 + clock 下降：把 thermal limit 作为待验证假设，但仍检查 power limit、fan behavior 和环境温度。
  4. clock 下降但温度不高：优先检查 power/voltage policy、负载阶段变化或系统级限制，不要直接下“散热差”结论。
  5. 温度高但性能稳定：这证明的是当前测试窗口内未观察到明显 drift，不代表温度“安全”；温度上限仍以具体硬件厂商规范为边界。
  6. 出现异常错误、异味、风扇失效或不可解释的不稳定：停止负载并回到安全检查，不通过“继续烤一会儿”来验证硬件。

最终 Evidence 应能回答：性能何时进入 steady state、是否持续漂移、漂移与哪些遥测同步，以及你没有证明哪些根因。

Decision Rule

热验收看“经过足够 warmup 后的 TG/clock/temperature 是否进入稳定区间”，而不是追求一个通用温度数字。
