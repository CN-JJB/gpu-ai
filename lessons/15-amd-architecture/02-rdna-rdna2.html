AMD 架构 2 — RDNA → RDNA2：Wave32、WGP、Infinity Cache

1. GCN 的 Wave64 为什么要改？

游戏/低延迟 workload 经常出现：

  • 短 shader；
  • 分支；
  • barrier；
  • 部分 lane 无效；
  • 需要快速把新 work 填进 execution units。

Wave64 的生命周期和资源粒度可能太粗。

2. RDNA 的大变化：Wave32

GCN:
wave64 primary

RDNA:
wave32 primary
wave64 compatibility

Wave32 的优势包括：

  • 更短 wave lifetime；
  • barrier 后更快重新填满；
  • 部分填充时浪费更少；
  • 适合更低延迟调度。
但别写：“AMD 改成和 NVIDIA 一样的 warp32”。Wave size 一样，不代表 scheduler、register file、cache、issue 方式一样。

3. 32-wide SIMD：一拍吃下 Wave32

经典 GCN 要 16-wide SIMD × 4 cycles 处理 wave64。

RDNA 的主路径让 Wave32 与 32-wide vector issue 更直接匹配。

Wave32
→ 32-wide SIMD
→ one vector instruction issue pass

4. WGP — Work Group Processor

RDNA 把两个紧密关联的 CU 组织成 WGP。

WGP
├─ CU0
├─ CU1
├─ shared scheduling/cache resources
└─ workgroup-level resource organization

WGP 让更多计算和带宽资源可以围绕一个 workgroup 配置。

5. Cache hierarchy 也跟着改

官方 HIP 文档的 RDNA 心智图：

per-CU L0
→ WGP-shared L1
→ global L2

比起 GCN，增加了更明确的 WGP-shared cache 层。

6. RDNA2：Infinity Cache

RDNA2 把大型 on-die cache 变成 Radeon memory hierarchy 的重要组成。

compute
→ L0/L1/L2
→ Infinity Cache
→ GDDR

目的：

reuse hits cache
→ fewer external GDDR transactions
→ effective bandwidth rises

7. Infinity Cache 不是额外显存

例如一个几十 GB 的 LLM 权重远大于 Infinity Cache。

它不能让 12 GB 卡“变成 12 GB + cache”。

对 LLM 的价值取决于：

  • 访问是否重复；
  • working set 是否局部；
  • kernel layout；
  • metadata / smaller tensors 是否能命中。

8. Radeon 架构现代 ≠ ROCm 一定支持

这对垃圾佬非常重要。

hardware architecture
and
official compute software support
are separate products

一张 RDNA2 卡的 CU/Wave32 没问题，但如果当前 ROCm prebuilt libraries 不支持 exact SKU/gfx target，实际 AI 体验仍会很差。

9. 买 AMD 消费卡时的第一条规则

不要只查：

"RDNA2 / RDNA3 / RDNA4?"

还要查：

exact gfx target
+ current ROCm support matrix
+ target backend

学生闭环 — RDNA / RDNA2

硬件门槛：L0；真机增强 L1/L2（任意受支持 AMD GPU）。

成本：0 元主路径；课程不要求为了这一节购买 AMD 卡。

风险：safe。

替代路径：无 AMD 卡完成 terminology trap + 官方架构调查；有卡才做 ROCm inventory。

能力目标

  • 正确使用 CU / WGP / wave32-wave64 / LDS / matrix path 等术语，不把 NVIDIA 名词硬翻译过去。
  • 区分 RDNA 图形导向与 CDNA 计算导向的产品目标。
  • 把“硬件有能力”和“ROCm/具体 backend 当前可用”分开。

小实验 / 反馈

做 Experiment 25：AMD generation terminology traps。有 AMD 卡时增强做 Experiment 26：real AMD ROCm inventory。

Retrieval Practice

  1. wave32、WGP 与 cache hierarchy 变化为什么会影响 kernel 与 occupancy 直觉？
  2. RDNA 的 wave32 与 CDNA 常见 wave64 对“warp=32”这种跨厂商说法有什么警告？
  3. 一张 AMD 卡支持某硬件指令，为什么还不能立刻推导 llama.cpp/vLLM 当前高效支持？
  4. 二手 AMD 卡便宜很多时，你要把哪些软件兼容成本计入 TCO？

完成证据

提交一张 RDNA / RDNA2 “术语→硬件→LLM”卡：execution group、compute block、on-chip memory、matrix path、memory system、当前 runtime 待验证项。

如何迁移

比较 NVIDIA/AMD 时只映射功能角色，不强求名词一一对应：warp↔wave、SM↔CU/WGP 只是近似层级，具体 scheduler/cache/resource 仍按架构查。
