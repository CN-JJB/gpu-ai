AMD 架构 1 — GCN → Vega：Wave64、CU、SGPR/VGPR、LDS

如果你只学过 NVIDIA，最容易犯的错误就是把 AMD 术语硬翻译成“AMD 的 warp / SM / CUDA Core”。这一节先用 AMD 自己的语言。

1. GCN 的最基本执行单位：Wave64

经典 GCN 把 64 个 work-item 组成一个 wavefront。

work-item × 64
→ one wave64

经典 GCN CU 的 SIMD 只有 16 lane 宽，因此一条 wave64 vector instruction 要分四拍执行：

lanes  0..15  → cycle 0
lanes 16..31  → cycle 1
lanes 32..47  → cycle 2
lanes 48..63  → cycle 3
关键：“wave64”描述的是逻辑执行组，不代表硬件一定有 64 个并排 ALU 一拍吃完。

2. CU — Compute Unit

GCN CU
├─ scalar path
├─ SIMD0
├─ SIMD1
├─ SIMD2
├─ SIMD3
├─ register files
└─ LDS

多个 wave 可以同时 resident。当一个 wave 在等 global memory 时，scheduler 可以切到别的 ready wave。

这和前面的 latency hiding 模型完全一致。

3. AMD 很重要的一组寄存器：SGPR vs VGPR

VGPR

one value per lane

例如每个线程自己的：

  • 坐标；
  • activation；
  • 指针偏移；
  • partial result。

SGPR

one scalar value shared across the whole wave

例如整个 wave 都一样的：

  • base pointer；
  • uniform loop bound；
  • constant；
  • wave-uniform condition。

如果一个值所有 lane 都相同，却塞进 VGPR，就是在浪费 vector register capacity。

4. LDS — Local Data Share

LDS 是 workgroup 内的低延迟共享 scratchpad。

global memory
→ LDS tile
→ many waves reuse
→ output

它就是你把 Slice 03 的：

  • tiling；
  • bank conflict；
  • reuse；
  • occupancy/resource pressure；

迁移到 AMD 时最重要的落点。

5. GCN occupancy 为什么也会被寄存器卡住？

more VGPR per thread
→ fewer waves fit
→ less latency hiding

SGPR、VGPR、LDS 都是有限的。

所以 AMD kernel tuning 不是“wave 越多越好”，而是和 NVIDIA 一样要平衡：

resource per wave
× active waves
× useful ILP
× memory behavior

6. Vega：GCN 路线开始认真拥抱低精度和 HBM

Rapid Packed Math

如果算法允许较低精度，就可以把较小数据打包进同一个 datapath，提高吞吐。

32-bit datapath slot
→ two lower-precision values
→ more ops per clock

这是现代 FP16/INT8/FP8 AI 路线之前的重要阶段。

HBM2 与 High Bandwidth Cache

Vega 高端产品把 HBM2 带进消费/compute 产品。

真正的长期趋势：

GPU compute gets faster
→ memory bandwidth becomes more important
→ package/memory architecture becomes a first-class design axis

7. 为什么 Vega 是分叉点

从这里以后，AMD 不再让一个架构同时承担所有目标：

GCN / Vega ancestry
      ├─ RDNA → graphics / low-latency
      └─ CDNA → HPC / AI / throughput

所以后面千万不要说：

RDNA2 → RDNA3 → CDNA3

这是两条不同产品/架构路线。

学生闭环 — GCN / Vega

硬件门槛：L0；真机增强 L1/L2（任意受支持 AMD GPU）。

成本：0 元主路径；课程不要求为了这一节购买 AMD 卡。

风险：safe。

替代路径：无 AMD 卡完成 terminology trap + 官方架构调查；有卡才做 ROCm inventory。

能力目标

  • 正确使用 CU / WGP / wave32-wave64 / LDS / matrix path 等术语，不把 NVIDIA 名词硬翻译过去。
  • 区分 RDNA 图形导向与 CDNA 计算导向的产品目标。
  • 把“硬件有能力”和“ROCm/具体 backend 当前可用”分开。

小实验 / 反馈

如何迁移

比较 NVIDIA/AMD 时只映射功能角色，不强求名词一一对应：warp↔wave、SM↔CU/WGP 只是近似层级，具体 scheduler/cache/resource 仍按架构查。
