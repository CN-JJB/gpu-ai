AMD 架构 4 — RDNA3 / RDNA4 + CDNA4 / CDNA5：AI 时代两条线都在加速

1. RDNA3：消费 GPU 也进入 chiplet

GCD
→ compute / core GPU logic

MCD
→ memory controller + Infinity Cache

这不是把两个完整 GPU 拼起来，而是把功能拆到不同 chiplet。

2. Dual-Issue VALU — 不是免费 2×

RDNA3 ISA 的 VOPD 可以在一个编码里打包两条 independent VALU operation，并行执行。

必须满足：

  • Wave32；
  • 两条 instruction independent；
  • register bank constraints；
  • operand restrictions；
  • compiler 成功配对。
peak dual issue
!=
every shader 2x throughput

3. RDNA3 第一次明确加入 AI Accelerator

消费 Radeon 开始有专门 AI acceleration。

但：

RDNA3 AI accelerator
!=
CDNA3 Matrix Core ecosystem

一个面向 graphics/desktop，另一个面向 Instinct AI/HPC。

4. RDNA4：FP8 / INT4 更靠近消费 GPU

当前 AMD RDNA4 页面明确写：

  • 第二代 AI accelerators；
  • FP8 / INT4；
  • 第三代 Infinity Cache；
  • 改进 on-chip scheduling。

AMD 还公开说明 FSR4 使用 RDNA4 的 FP8 WMMA 路径。

对本地 LLM 的正确结论：硬件已经有低精度 AI 能力。
不能推出：llama.cpp / PyTorch 的某个 Q4 一定已经映射到这些单元。

5. RDNA4 仍支持 Wave32 / Wave64

当前 ISA 同时支持两种 wave size。

Wave64 的部分 vector/memory instruction 在硬件上会分低 32 lane / 高 32 lane 两次处理。

所以 wave size 不是纯语法选项，它影响：

  • issue；
  • divergence；
  • register/resource；
  • latency。

6. CDNA4：MI350 继续拉高低精度 + HBM

当前 AMD CDNA 页面记录：

  • HBM3E；
  • Matrix Core；
  • MXFP4/MXFP6/MXFP8；
  • sparse low-precision paths；
  • gfx950 当前 ROCm 支持。

7. 2026 最新：CDNA5 / MI400

截至 2026-08-27，AMD 已公布/推出 CDNA5 路线。

最值得注意的不是数字，而是架构方向：

new WGP
+ Wave32
+ AI math engine
+ MXFP4/6/8
+ HBM4
+ rackscale fabric

这很有意思：

Wave32 / WGP
曾经是 RDNA 的代表性变化

现在
CDNA5 compute branch
也使用新的 WGP / Wave32 方向

说明两条线虽然用途不同，但执行组织会互相吸收有效思想。

8. 但当前 ROCm 支持要单独看

硬件页面已经有 CDNA5；当前 ROCm 7.14 标准支持矩阵主要列到 CDNA4。

new hardware exists
!=
your chosen stable ROCm package already supports it

9. AMD 垃圾佬的最终检查顺序

  1. exact Radeon/Instinct model；
  2. architecture；
  3. gfx target；
  4. official ROCm support；
  5. VRAM/HBM/GDDR capacity；
  6. memory bandwidth / Infinity Cache；
  7. matrix/AI data types；
  8. llama.cpp / PyTorch current backend；
  9. PP/TG benchmark；
  10. 电源/散热/二手风险。

学生闭环 — RDNA3 / RDNA4 / CDNA4+

硬件门槛：L0；真机增强 L1/L2（任意受支持 AMD GPU）。

成本：0 元主路径；课程不要求为了这一节购买 AMD 卡。

风险：safe。

替代路径：无 AMD 卡完成 terminology trap + 官方架构调查；有卡才做 ROCm inventory。

能力目标

  • 正确使用 CU / WGP / wave32-wave64 / LDS / matrix path 等术语，不把 NVIDIA 名词硬翻译过去。
  • 区分 RDNA 图形导向与 CDNA 计算导向的产品目标。
  • 把“硬件有能力”和“ROCm/具体 backend 当前可用”分开。

如何迁移

比较 NVIDIA/AMD 时只映射功能角色，不强求名词一一对应：warp↔wave、SM↔CU/WGP 只是近似层级，具体 scheduler/cache/resource 仍按架构查。
