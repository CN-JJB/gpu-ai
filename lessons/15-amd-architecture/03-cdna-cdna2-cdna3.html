AMD 架构 3 — CDNA → CDNA2 → CDNA3：Instinct 的 AI/HPC 路线

1. CDNA 为什么要从 graphics 架构分出去？

游戏 GPU 要：

  • 低延迟；
  • 高频；
  • 图形固定功能；
  • GDDR/cache 性价比。

HPC/AI accelerator 更在乎：

  • HBM bandwidth/capacity；
  • matrix throughput；
  • FP64；
  • GPU↔GPU fabric；
  • 大规模多卡。

因此 CDNA 是专用 compute architecture。

2. MI100 / CDNA：Matrix Core 正式成为中心

AMD 当前 HIP 术语：

MFMA
= Matrix Fused Multiply-Add

普通 VALU：

lane-wise vector arithmetic

MFMA：

whole matrix tile
→ one wave-wide matrix instruction
→ accumulator tile

它和 NVIDIA Tensor Core 解决类似问题，但硬件/ISA 不一样。

正确迁移：比较“支持什么 datatype、tile、accumulator、library”。
错误迁移：拿“Matrix Core 个数 ÷ Tensor Core 个数”算性能。

3. CDNA + HBM + Infinity Fabric 是一个系统

Matrix Core
needs
HBM bandwidth
+
Infinity Fabric / xGMI
+
ROCm libraries

没有足够数据供给和 library kernel，Matrix Core 峰值用不上。

4. CDNA2：不只 AI，还把 FP64 做进 matrix path

MI200/CDNA2 加强：

  • matrix FP64；
  • BF16/FP16；
  • HBM2e；
  • multi-die；
  • Infinity Fabric scale-up。

这说明 CDNA 是：

AI + scientific HPC

而不是“没有图形单元的 gaming GPU”。

5. 多 die 后，互联又成为 Roofline

MI250-class 不是简单把 CU 复制两份。

die A compute
↔ fabric
↔ die B compute

只要工作跨 die，Slice 11 的：

  • communication bytes；
  • bandwidth；
  • sync；
  • imbalance；

全部重新出现。

6. CDNA3：XCD + I/O Die + HBM3

MI300 引入 Accelerated Compute Die：

XCD
→ CU + lower cache

IOD
→ memory / package fabric / higher shared resources

HBM3
→ high-bandwidth capacity

7. MI300A 与 MI300X 必须分开

MI300A

Zen 4 CPU chiplets
+ CDNA3 XCD
+ shared HBM
+ coherent package

MI300X

GPU-focused XCD composition
+ very large HBM capacity

同样“CDNA3”，系统结构已经不同。

8. FP8 / TF32 / sparsity

CDNA3 Matrix Core 加入现代 AI precision：

  • FP8；
  • TF32；
  • sparse data paths；
  • 延续 FP16/BF16/INT8/FP32/FP64。

但仍遵守 Slice 13：

model storage quant
!= native matrix datatype
