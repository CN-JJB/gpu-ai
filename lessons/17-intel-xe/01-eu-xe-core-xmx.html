Intel Xe 1 — EU → Xe-Core → XMX：别拿“核心数”跨生态硬比

1. Intel 老 GPU 常见术语：EU

Intel Gen Graphics / Xe-LP 时代最常见：

EU = Execution Unit

EU 是多线程 SIMD execution building block。

第一条规则：1 EU ≠ 1 CUDA core。它们不是相同粒度的硬件单位。

2. Xe 架构开始换一套更清楚的层级

Intel 当前 Xe 文档使用：

GPU
→ Xe Stack
→ Xe-Core
→ Vector Engine
→ hardware threads
→ SIMD lanes

3. Vector Engine

Intel 当前定义它为 Xe GPU 最小的 thread-level building block。

一个 Vector Engine：

  • 有多个 hardware thread；
  • 每个 thread 有 GRF；
  • 执行 SIMD 16/32 等向量指令；
  • 支持 FP/INT 多种 datatype。

4. Xe-Core

一个 Xe-Core 里可以有：

Vector Engines
+ XMX Matrix Engines
+ shared L1
+ SLM

这比只看“EU 数”更接近现代 Intel GPU 的资源组织。

5. SLM

Intel 的低延迟 cooperative scratchpad：

SLM = Shared Local Memory
生态workgroup-local scratchpad
NVIDIAshared memory
AMDLDS
Applethreadgroup memory
IntelSLM

同样适合：

  • GEMM tile；
  • attention tile；
  • reduction；
  • softmax。

6. XMX：Intel 的 matrix engine

XMX
= Xe Matrix Extensions

它面向 systolic / DPAS-style matrix/dot-product 工作。

正确比较方式：

NVIDIA Tensor Core
AMD MFMA
Intel XMX

→ all accelerate matrix workloads
→ but instruction/data/layout differ

错误：

160 XMX
÷
320 Tensor Core
= half performance

7. Xe-LP 与 Xe-HPG 不要混

集成 Iris Xe / Xe-LP 的 EU 结构和 Arc Alchemist 的 Xe-Core/XMX 结构不是同一件事。

所以：

"Intel Xe"

仍然不够具体。

8. Alchemist / Xe-HPG

Arc A 系列把：

  • Xe-Core；
  • XMX；
  • 独立 GDDR VRAM；
  • 现代 media/RT block；

带进 Intel 消费 dGPU。

9. Battlemage / Xe2

Arc B 系列进入 Xe2：

  • 第二代 Xe-Core；
  • 更新 Vector Engine；
  • 更新 XMX；
  • cache/execution 继续调整。

不要把 Battlemage 理解成：

A-series
+ more cores

它是新的 Xe2 generation。

10. Subgroup width 也不是固定 32

Intel current architecture tables 对不同家族列出：

8 / 16 / 32
or
16 / 32

所以跨生态统一结论应该是：

query / compile for actual subgroup model

而不是背一个数字。

学生闭环 — EU → Xe-Core / XMX

硬件门槛：L0；真机增强 L1/L2（受支持 Intel GPU）。

成本：0 元主路径；课程不要求购买对应平台。

风险：safe。

替代路径：没有 Intel GPU 就完成 terminology trap；有 Arc/Xe 再做 XPU/SYCL inventory。

能力目标

  • 区分 EU-era 与 Xe-Core-era 的执行结构和 XMX matrix path。
  • 解释 oneAPI/SYCL、Level Zero、PyTorch XPU、llama.cpp SYCL 是不同软件层。
  • 把 Intel GPU 的低价/显存优势与 backend maturity、驱动、kernel 支持一起评估。

小实验 / 反馈

做 Experiment 29：Intel Xe terminology traps；有 Intel GPU 时做 Experiment 30：real Intel XPU/SYCL inventory。

Retrieval Practice

  1. 为什么旧 Intel EU 术语与 Xe-HPG/HPC 的 Xe-Core/Vector/Matrix Engine 不能混着数？
  2. 为什么 XMX 的存在只证明 hardware capability，不能证明某 quant/backend 的实际 kernel path？
  3. 用什么证据区分“驱动看到了 Arc”和“LLM runtime 正在用正确 backend”？
  4. 如果 A770 价格很低，但常用框架缺功能，时间成本应该放到哪一类 TCO？

完成证据

提交一张 Intel software ladder：GPU identity → driver/Level Zero → SYCL/XPU runtime → LLM backend → exact model/quant path，并标出每层证据来源。

如何迁移

以后碰到任何“新 GPU 支持 AI”的宣传，都沿同一条链验证：硬件 matrix capability → compiler/runtime exposure → framework/backend integration → model-format/kernel coverage → workload measurement。
