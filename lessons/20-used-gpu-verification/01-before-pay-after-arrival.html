Used GPU Verification · L0→L2

二手 GPU 验证：付款前筛风险，到货后用证据决定 ACCEPT / REVIEW / REJECT

二手显卡不是“同型号随机抽一张”。你买到的是一块有具体序列、维修史、温度、显存、风扇、接口和供电状态的物理设备。本课把验卡拆成付款前与到货后两阶段，并坚持安全、可回滚、可留证据。

Prerequisite Check

你应理解市场价格证据、hard gate、UNKNOWN 与目标应用 benchmark。不会拆卡、不会刷 BIOS 完全没关系；本课默认不做危险维修操作。

真实问题：卖家发了 FurMark 截图，能不能证明这张卡“没问题”？

不能。截图可能说明某时刻某负载跑过，但通常缺少：

  • 是否就是这张物理卡；
  • 完整测试时长；
  • 显存错误；
  • 热点/显存温度；
  • PCIe link 状态；
  • 崩溃/驱动 reset 历史；
  • 目标 LLM workload 是否稳定。

卖家证据有价值，但强度低于你自己到货后可重复的测试。

1. 付款前：目标是减少明显坏单，不是远程证明健康

向卖家索取能降低身份/状态不确定性的材料：

  • 清晰正反面、接口、螺丝/封签、散热器/背板照片；
  • 型号标签/序列（必要时遮部分隐私）；
  • 设备识别截图：型号、VRAM、driver、PCIe link；
  • 短负载视频或监控截图：温度、热点、风扇、功耗、频率；
  • 是否维修/进水/更换显存/刷 BIOS/矿用的明确回答；
  • 退货规则与测试期。

如果卖家拒绝一切基本验证，不等于必坏，但风险应进入价格。

2. 身份核对：防止“同名不同卡”

到货后先做只读 identity：

physical label / serial
↕
PCI vendor/device/subsystem
↕
GPU name / VRAM / VBIOS identity
↕
benchmark session UUID / PCI bus

不要只看软件显示的营销名称；异常 VBIOS、改卡、OEM 变体可能造成误判。

3. 外观检查：不开机前先找机械风险

  • PCB 是否弯曲、裂纹、烧蚀；
  • 金手指是否严重磨损/腐蚀；
  • 供电插座是否熔化、发黑；
  • 风扇是否卡顿、明显异响；
  • 散热器是否松动、螺丝是否异常缺失；
  • 液体/锈蚀痕迹。
安全：发现供电接口熔化、明显烧蚀、液体残留等严重问题，不要为了“测试一下”强行上电。优先退货/专业检查。

4. 第一次上电：先低风险确认，不直接满载

推荐顺序：

  1. 确认 PSU/连接器/线材正确；
  2. 系统冷启动并检查是否正常枚举；
  3. 读取 idle 温度、风扇、功耗、PCIe link；
  4. 跑短、温和负载；
  5. 确认无 artifact、reset、异常噪声后再进入长负载。

不要刚收到未知状态二手卡就超频、加压、刷 BIOS。

5. PCIe link：为什么“能识别”还不够？

卡可能只以异常低宽度/速率链接，原因可能是插槽、主板 bifurcation、接触、riser、BIOS 或硬件问题。记录 idle 与 load 下的 negotiated link；某些平台 idle 会降速省电，需结合负载状态解释。

6. 显存测试：LLM 最怕“偶发错误”

显存问题可能表现为：

  • 显存测试报错；
  • 长负载随机崩溃；
  • CUDA/HIP kernel error；
  • 模型输出异常但难复现；
  • driver reset / Xid 等错误。

单次图形 benchmark 不一定覆盖全部显存。应使用适合设备的安全 memory test，并保留错误计数/日志。

7. Thermal：看 GPU core 温度还不够

如果设备能报告 hotspot/memory junction，应一起观察。重点不是追求某个网络流传的“完美温度”，而是：

  • 是否快速冲到限制并降频；
  • core 与 hotspot delta 是否异常；
  • memory 温度是否长期处于高风险区域；
  • 风扇是否以异常高转才能维持；
  • 相同负载下 clocks/功耗是否稳定。

8. 长时间稳定性：短跑通过 ≠ 稳定

至少做两类 workload：

  1. 通用 GPU/显存压力，覆盖温度和稳定性；
  2. 你的目标 LLM workload，覆盖实际 kernel、显存、runtime。

长跑要记录时间轴，而不是只保存最后一帧截图。

Worked Example：一张卡 10 分钟没报错，但 40 分钟后 TG 下降 20%

不要立刻判坏。检查：

temperature / hotspot trend
→ clocks trend
→ power limit
→ fan behavior
→ host/system thermal
→ background load
→ driver errors

如果温度升高同时 clocks 稳定下降，thermal throttling 是强候选；如果温度稳定但出现 PCIe/driver error，则方向不同。先建立时间相关性，再下结论。

9. ACCEPT / REVIEW / REJECT：把健康与证据强度分开

课程把“技术健康结果”与“证据强度”分开：

  • ACCEPT：当前测试协议内未发现阻断问题；
  • REVIEW：有异常/未知，需要更多验证；
  • REJECT：出现明确失败或不满足硬性要求。

强证据也可能得到 REJECT；弱证据即使看起来正常，也不能升级成高置信 ACCEPT。

10. 什么情况直接 REJECT？

你的个人协议应事先写明，例如：

  • 显存测试出现可重复错误；
  • 目标负载反复 driver reset/crash；
  • 身份/容量与卖家描述不符；
  • 供电接口/PCB 有明确安全损伤；
  • 无法满足目标 PCIe/稳定性 hard gate；
  • 卖家隐瞒关键维修/改卡事实且超出可接受风险。

阈值要在看到结果前定义，避免 sunk-cost bias。

Why it matters

  • 同型号二手卡的个体健康差异可能远大于新卡。
  • 卖家证据只能降低不确定性，不能替代买家可重复测试。
  • LLM 长负载可暴露短游戏测试看不到的 memory/thermal 问题。
  • 预先写 reject criteria 可以减少“都买了就凑合”的心理偏差。
  • 安全外观检查应先于满载。

常见误区

  • “FurMark 过了 = 显存一定没问题”——覆盖范围不足。
  • “核心温度不高 = 散热健康”——hotspot/memory/fan/clocks 也要看。
  • “卖家说没修过 = C3 强证据”——只是 seller claim。
  • “能进系统 = PCIe/VRAM 全正常”——只证明最基本枚举。
  • “收到卡先刷最新 BIOS/超频测试”——破坏可归因性并增加风险。

小实验：写自己的到货 60 分钟协议

现在不需要有卡。把第一小时拆成 0–5、5–15、15–30、30–60 分钟，写每阶段：测试、记录字段、停止条件。禁止包含超压/危险拆修。

预期观察：协议应从低风险 identity/idle 逐步增加负载，并在任何明确安全异常时停止。

无二手卡路径

L0 使用现有 Experiment 87 / I44 模板和 synthetic fixture 学会读 acceptance evidence。Synthetic 只能证明流程，不能当某张真实卡健康证明。

排错

  • 测试工具互相冲突：一次只跑一类主要压力，避免资源争抢污染结果。
  • 错误偶发无法复现：保留时间、温度、clocks、driver log，增加可控重复，不先改 BIOS。
  • 换线/换槽后恢复：记录变更，说明问题可能在平台链路而非 GPU 本体。

Retrieval Practice

  1. 卖家负载截图能说明什么，不能说明什么？
  2. 为什么到货后先 identity/外观/idle，而不是直接满载？
  3. PCIe “能识别”为什么不等于 link 正常？
  4. 显存错误为什么对 LLM 特别危险？
  5. ACCEPT/REVIEW/REJECT 与证据强度为什么要分开？
  6. 为什么 reject criteria 应在测试前写？

Decision Rule

任何二手卡只有在身份、链路、显存、thermal、稳定性和目标 workload 按预定义协议通过后，才可标为 ACCEPT。未知项保持 REVIEW；可重复硬失败直接 REJECT。不要为了保住交易修改阈值。

Transfer

相同方法可迁移到二手服务器、SSD、Mac、主板：卖家证据预筛 → 到货低风险 identity → 逐级压力 → 预定义 acceptance。

完成证据

完成本课后，保留一份 learner-owned completion artifact，至少包含：

  • 用自己的话画出或写出本节最小 mental model，并标出关键变量/资源层；
  • 完成本节小实验、worksheet 或无硬件 fallback；有真机时链接 raw Evidence，没有真机时明确标 L0 / DOCUMENTED / DEFERRED-HARDWARE；
  • 写一条绑定 Evidence 的 PASS / FAIL / UNKNOWN / BLOCKED 结论，说明它怎样影响本地 LLM 的容量、性能、兼容、成本或风险判断；
  • 写一句明确 non-claim：这份证据还不能证明什么。

只写“看完了”或抄规格表不算完成。课程要的是可复查的推理产物，而不是阅读打卡。
