Apple Silicon 3 — M1 → M5：GPU、Neural Engine、MLX 到底谁在跑 LLM？

1. M1：先建立 SoC + Unified Memory 世界

M1 的真正历史意义：

Mac
→ Apple-designed SoC
→ CPU + GPU + Neural Engine
→ one unified memory architecture

从这一代开始，Mac 本地模型不再天然受一块小离散 VRAM 限制。

2. M2：主要是 scale-up

M2 增加 GPU / memory / media 能力，但没有改变最基本的软件执行抽象。

所以课程不会为了“每年一章”硬凑一个新架构。

3. M3：GPU architecture 真正大改一次

Apple 把 M3 称为全新的 GPU architecture。

Dynamic Caching

传统资源分配容易出现：

reserve for worst case
→ some local resource unused
→ lower average utilization

M3 Dynamic Caching 的方向：

hardware dynamically assigns local memory
based on actual workload demand

对课程最重要的不是 marketing speedup，而是：

GPU local resource allocation 本身可以成为硬件动态调度问题。

Ray tracing / mesh shading

它们是重要 graphics feature，但不要写：

ray tracing core
→ faster llama.cpp

4. M4：AI/memory scale 继续提高

M4 强化：

  • GPU；
  • Neural Engine；
  • memory bandwidth；
  • CPU ML capabilities。

对本地 LLM，仍然需要具体看：

capacity
bandwidth
backend
PP/TG

5. M5：最容易被搞混的一代

M5 给每个 GPU core 加入：

Neural Accelerator

Apple 提供 Metal 4 Tensor APIs 让开发者直接利用这类 GPU neural hardware。

6. 但是 M5 同时还有独立 Neural Engine

M5 SoC
├─ GPU
│  ├─ shader execution
│  └─ Neural Accelerator per GPU core
│
└─ Neural Engine
   └─ separate accelerator
M5 GPU Neural Accelerator ≠ Apple Neural Engine。

7. Core ML 可以明确选择执行单元

Core ML API 有：

cpuOnly
cpuAndGPU
cpuAndNeuralEngine
all

所以 Apple 自己的 API 都把 GPU 和 Neural Engine 当成不同 compute units。

8. MLX 又是哪条路？

MLX 的 Apple-Silicon 设计重点：

one unified-memory array
→ CPU stream
or
→ GPU stream

当前 MLX 文档的标准 device 类型是 CPU 和 GPU。

因此：

MLX GPU
!= Neural Engine

9. llama.cpp Metal 呢？

llama.cpp 的 Metal backend 主要是 GPU backend。

即使 M5 硬件新增 GPU tensor acceleration，runtime 也必须：

  1. 正确识别 hardware；
  2. 用正确 Metal language/API 编译；
  3. 正确映射 quant/matmul kernel；
  4. 通过 correctness tests；
  5. 实际 dispatch。

所以：

new accelerator exists
!=
your current llama.cpp binary uses it

10. 本地 LLM 怎么选 Apple 执行路径？

路径适合问什么
llama.cpp MetalGGUF、本地推理、Metal GPU PP/TG
MLX / MLX-LMApple-Silicon-native CPU/GPU unified-memory ML
Core MLApple framework deployment, possible ANE/GPU/CPU selection
CPU-onlybaseline / small ops / compatibility

11. Apple 买机优先级

跑大型本地 LLM：

  1. unified-memory capacity：先保证装得下；
  2. memory bandwidth：decode 很关键；
  3. runtime/backend：能不能用 GPU/new tensor path；
  4. GPU compute：prefill/large GEMM；
  5. thermal/power：持续负载；
  6. 价格/不可升级性：Apple RAM/GPU 后买基本不能升级。

12. 最后一句

Apple Silicon 的优势不是
"像独显一样但是显存更大"

而是
"把 CPU/GPU/accelerators 放进
同一个高带宽统一内存 SoC，
让软件重新设计数据和执行边界"
