Benchmark Manifest：把“我跑了个测试”变成可复现证据

一个 token/s 数字几乎没有上下文。Manifest 的作用，是把硬件、模型、runtime、执行设置、prompt、协议、质量身份与唯一 intentional variable 固定下来，使未来的你能回答：这个数字到底代表什么？

Prerequisite Check

你应理解一次只改一个语义变量、PP/TG、model artifact、prompt token identity 和 quality gate。

真实问题：为什么两张“同一模型同一 3090”的 benchmark 仍可能不可比？

因为它们可能使用不同 llama.cpp commit、quant 文件、context、prompt token 数、GPU layers、flash attention、KV type、thread count、power limit、warmup 与重复次数。

1. Manifest 的四层

fixed protocol
+ exact identities
+ variant blocks
+ audit links

固定协议描述比较规则；identity 绑定实际对象；variant 记录硬件/runtime/model/execution/prompt；audit 指向原始命令与结果。

2. Exact identity：名字不是证据

应优先保存：

  • GPU device identity/profile hash；
  • model artifact SHA/bytes/source revision/quant；
  • runtime commit/version/backend/build；
  • prompt rendered/token-ID hash；
  • quality corpus/identity hash。

“RTX 3090 + Qwen 8B + llama.cpp”太粗，无法排除多个实际对象。

3. Protocol：在看到结果前冻结

例如：

PP tokens = 512
TG tokens = 128
warmup = 1
repetitions = 5
quality corpus = exact SHA

先定义协议再测试，减少为了得到好看的结果临时改参数。

4. Intentional variable：写语义路径，不只写备注

例如：

variant.execution.flash_attention
variant.execution.kv_k
variant.model
variant.runtime
variant.hardware

如果比较的是 quant artifact，intentional variable 应落到 model；如果仅切 FA，则落到 execution。不同变量类型后续可使用不同质量归因路径。

5. Audit：为什么要保留 command.json 和 raw result？

manifest 是声明，原始命令/输出是执行证据。只有二者绑定，才能检查“宣称的 model path 是否真的是命令里的 -m”“profile SHA 是否真对应文件”。

Worked Example：两个结果都是 50 TG/s

A 使用 Q4、8k context；B 使用 Q6、2k context。单看 50 完全相等；manifest 告诉你它们不是同一 cohort，不能得出“Q4/Q6 一样快”。

真正可比的 A/B 应固定所有无关字段，只改变你想研究的变量。

6. System comparison：诚实承认不能单变量

比较 3090 CUDA 与 7900 XTX ROCm 时，hardware、runtime/backend 同时变化。不要伪造因果归因；标为 system comparison，描述整个系统组合结果即可。

7. Synthetic 与 real

Synthetic fixture 可以验证 schema、parser、gate，但不能进入真实 benchmark catalog。manifest 中的 synthetic/provenance 语义必须明确。

Why it matters

  • 让 benchmark 可重跑、可审计。
  • 避免不同模型/协议的数字被拼成排行榜。
  • 支持自动 gate 与 comparison tooling。
  • 让失败结果也保留完整上下文。

常见误区

  • “命令行全贴了就够”——仍缺 artifact/profile/prompt/quality identity。
  • “型号相同就是同硬件条件”——power/thermal/profile 可不同。
  • “两个系统差异可以归因某一硬件 feature”——多变量 system comparison 不允许。
  • “Synthetic 通过 gate 就证明真实 GPU”——只证明工具行为。

排错

  • validator 说多个字段变化：决定是修成单变量还是明确降级 system comparison。
  • artifact hash 对不上：不要改 manifest 假装匹配，重新确认文件。
  • prompt count 不同：回到 Experiment 57 固定 token identity。

Retrieval Practice

  1. Manifest 比单条 benchmark 数字多保存了哪些关键上下文？
  2. 为什么 protocol 应在看到结果前冻结？
  3. intentional variable 为什么应该写语义路径？
  4. manifest declaration 与 raw command evidence 各自证明什么？
  5. 什么时候必须标 system comparison？
  6. Synthetic fixture 能证明什么、不能证明什么？

Decision Rule

没有 exact identity + fixed protocol + raw audit evidence 的性能数字，不进入正式 comparison。多个语义块一起变化时只做 system comparison，不做单因素因果归因。

Transfer

Manifest 思想同样适用于功耗、热稳态、二手验卡和服务 SLO：任何结果都应绑定“对象、条件、协议、原始证据”。
