LLM 架构 7 — 不是每层都要保存完整 KV：Sliding、Hybrid 与 Latent KV

1. 先复习旧公式

KV
=
2 × L × Hkv × Dh × bytes × context

它隐含了一个大前提：

每一层
都缓存
整个 context
的普通 K/V

现代模型可能不满足。

2. Sliding Window：这一层只直接看最近 W 个位置

sequence length = S
window = W

cached positions
≈ min(S,W)

当：

S >> W

local layer 的 rolling KV 不再随完整 S 线性增长。

3. 但这不等于“模型只能记 W token”

上一层的 token 表示本身已经混入了更早的信息。

多层 local attention 可以逐层传播信息。

Hybrid 模型还可以穿插 full/global attention。

Direct window、effective context、KV cache size 是三件不同的事。

4. Hybrid 怎么算？

假设 32 层：

8 full
24 local
window = 4096

KV：

2 × Hkv × Dh × bytes
×
[
8×S
+
24×min(S,4096)
]

5. 用 32k context 算

假设：

Hkv=8
Dh=128
FP16
结构32k KV
32 层全 full4 GiB
32 层全 local W=4k0.5 GiB
8 full + 24 local1.375 GiB

6. 拉到 128k

结构128k KV
全 full16 GiB
全 local0.5 GiB
8 full + 24 local4.375 GiB

所以只看：

max_position_embeddings = 131072

根本不够判断显存。

7. Prefill compute 也变

Full attention：

O(T²)

Local attention：

O(TW)

概念上长 prompt 的 attention 工作也跟着下降。

真实 kernel 仍要看 backend。

8. Decode 也少读历史

Full layer：

read S cached positions

Local layer：

read at most W

但是 FFN weights 还是照读。

所以 KV/attention traffic 降低后，TG 可能更明显暴露 FFN weight bandwidth。

9. Hybrid 是现实里很重要的折中

例如 Gemma 2 就使用 local-global attention 交错的设计。

思路是：

大多数层便宜地 local
+
部分层保留 global access

具体 pattern 不能靠猜，要看 model config/paper。

10. MLA 又走另一条路

Sliding Window 减的是：

缓存多少 position

MLA 类方法减的是：

每个 position 缓存多宽

DeepSeek-V2 的 Multi-head Latent Attention 会把 KV 信息压到较小 latent state，再围绕 attention 做投影。

11. 所以通用 KV 心智模型升级成

KV/state bytes
=
Σ layers
(
cached positions
× cached state width
× bytes
)

这比背：

2 × L × Hkv × Dh × S

更通用。

12. DeepSeek-style config 里你可能看到

kv_lora_rank
qk_rope_head_dim

在确认是对应 MLA 实现后，可以把它们当 compressed state 的关键维度来研究。

但绝不能把 kv_lora_rank + qk_rope_head_dim 当全世界所有 latent attention 的万能公式。

13. 压缩 KV 不是免费午餐

你通常在做：

less cached bytes
↔
more projection/reconstruction work

这对 bandwidth-bound decode 很可能是好交易，但实际速度仍要 benchmark。

14. 以后 Model Dossier 怎么写？

full attention
→ ordinary formula

confirmed local layers
→ min(S,W)

hybrid
→ per-layer sum

latent/compressed KV
→ model-specific cached state width

unknown
→ KV EXACTNESS = UNKNOWN

宁可写 UNKNOWN，也不要套错公式。

学生闭环 — Sliding / Hybrid / Latent KV

硬件门槛：L0 主路径；真实模型/硬件只用于增强。

成本：0 元。

风险：safe。

能力目标

  • 把“模型/输入/质量/benchmark 身份”变成可审计对象。
  • 能指出公式或配置的适用边界，不把近似写成事实。
  • 为后续硬件选择提供可重复的 workload contract。

小实验 / 反馈

做 Experiment 54：sliding/hybrid KV model；再做 Experiment 55：real attention/KV architecture。

Retrieval Practice

  1. Sliding Window Attention 为什么能限制部分层的 KV 增长，却不等于整个模型 KV 一定固定？
  2. Hybrid local/global attention 的 KV 预算为什么要按层类型分开？
  3. MLA/latent KV 为什么不能套标准 Hkv×Dh 公式直接算？
  4. 面对新 KV 结构，最安全的第一步是什么？

完成证据

选一个 sliding/hybrid/latent-KV 模型，写出标准公式哪里还适用、哪里失效，以及你从 config/论文/runtime 哪一处确认真实 cache 结构。

如何选择 / 迁移

遇到新模型或新 backend 时，优先冻结 身份 + 输入 + protocol，再谈性能或质量；不可比的数据宁可 BLOCKED，也不要硬排排行榜。
