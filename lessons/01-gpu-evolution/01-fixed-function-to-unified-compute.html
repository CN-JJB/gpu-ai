GPU 为什么从固定功能走向统一计算？

今天的 CUDA Core、warp、Tensor Core 并不是一夜出现的。先理解为什么 GPU 必须越来越可编程，后面的架构术语才会连成因果模型。

真实问题

为什么一块最初为画图而生的芯片，后来会成为 LLM 的主力计算平台？

五个阶段

固定功能→ 可编程 Shader→ Unified Shader→ GPGPU / CUDA→ Tensor / Matrix

1. 固定功能：很快，但只能走设计好的路

早期 GPU 把 3D 渲染中的大量重复、并行工作做成专门流水线。对既定工作很高效，但硬件能表达的效果受到流水线限制。NVIDIA 当前 CUDA 文档也把 GPU 的早期形态概括为为实时 3D 图形服务的固定功能硬件。

2. 可编程 Shader：把做什么交给程序

2001 年 NVIDIA Research 对 GeForce3 的 user-programmable vertex engine 的描述很有代表性：它从高度优化的固定功能 pipeline 演进而来，让开发者能在顶点阶段运行自己的程序，同时还要保住图形工作所需的并行吞吐。

真正值得记的是 GPU 开始从固定机器变成可编程并行机器。

3. Unified Shader：为什么不要把工位永久焊死？

假设芯片一半工位永远只做 Vertex，另一半永远只做 Pixel。如果某个 workload 突然 80% 都是 Vertex，Pixel 工位会闲着，而 Vertex 工位排队。统一执行池让可编程资源能随 workload 变化重新分配。

纠偏：Unified 不代表整颗 GPU 变成同一种单元。纹理、ROP、内存控制器，以及后来的视频、光追、矩阵模块仍可高度专用。

4. CUDA/GPGPU：不用再假装自己在画图

GPU 有大量可编程执行资源后，还需要正常的计算编程模型。NVIDIA 在 2006 年推出 CUDA，把线程、block、shared memory、同步等概念直接暴露给通用计算。图形与计算仍然共存。

5. Tensor Core：历史又回到专用化

深度学习把矩阵乘加变成极高价值热点。Volta 把 Tensor Cores 加进 SM，用专门数据通路提高矩阵计算吞吐和能效；AMD CDNA 同样包含矩阵加速路径。

现代 GPU = 大量通用并行执行资源 + 高价值热点专用单元 + 高带宽内存系统。

这和本地 LLM 有什么关系？

  • LLM 大量计算落到矩阵/向量运算，所以矩阵硬件和低精度支持很重要。
  • 但有 Tensor Core 不等于一定快：kernel/backend、显存容量、带宽、数据类型都会改变结果。
  • 游戏和 LLM 都使用 GPU，但 workload 不同，不能只拿游戏 FPS 推导 LLM 价值。
