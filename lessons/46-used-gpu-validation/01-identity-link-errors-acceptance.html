二手显卡验收 — “系统显示型号正常”为什么远远不够？

1. 先把卖家描述变成可检查的字段

型号
VRAM
板卡/子厂
接口
工作状态

然后逐个找独立证据。

外壳贴纸和一个 GPU 名称字符串都只是证据之一。

2. 身份至少交叉看

PCI vendor/device/subsystem
BDF / UUID
runtime product name
VRAM
VBIOS
board info

字段互相一致，可信度才提高。

3. 对垃圾佬最关键的是 VRAM

你买卡就是为了 24 GiB：

卖家：24 GiB
驱动/runtime：约 12 GiB

这不是小误差，是购买关键 claim 冲突。

4. PCIe Gen1/x1 先别急着退货

你可能在 idle 时看到低 current state。

current link
!= max capability

而且主板、CPU lanes、riser、bifurcation 都可能限制链路。

5. 真正要记两组

max/capable Gen + width
current negotiated Gen + width

如果要判断负载状态，再在普通 workload 下观察。

6. ECC N/A 不是“0 错误”

很多消费卡没有你期待的 ECC/RAS 字段。

NOT_SUPPORTED
!=
0 errors

写 N/A，继续用其他证据。

7. 什么错误更值得警惕？

uncorrectable ECC/RAS
repeated XID/runtime error
PCIe recovery/replay异常增长
bad pages
普通 inference 反复 crash

但每个字段是否支持，要看具体卡和驱动。

8. 一次 30 秒通过意味着什么？

这个 30 秒窗口没看到错误

只意味着这个。

不意味着：

永久可靠
所有显存地址都好
所有 DP/HDMI 都好

9. 最有价值的测试是你真的要跑的 workload

直接复用课程 sustained TG：

固定 model SHA
固定 runtime
重复 TG
记录 temp / clock / errors

因为你买卡就是为了 Local LLM。

10. 温度高也别单独判死刑

温度
+
clock
+
TG drift
+
limiter/event

一起看。

11. 显示坏和计算坏不是一回事

如果你只做 headless inference：

HDMI 坏
但 compute 稳定

可能是你愿意接受的折价缺陷。

但必须明确记录，不能当“全好”。

12. 默认课程不做什么？

刷 VBIOS
超频/降压
改 power limit
错误注入
破坏性 VRAM stress

先把只读证据和普通工作负载做扎实。

13. 最后的决定只有三类

ACCEPT
REVIEW
REJECT

不要写：

“看起来应该没问题”

14. 一个好验收包

seller claim
+ identity
+ VRAM
+ PCIe
+ error state
+ sustained TG
+ thermal
+ physical/display
→ decision

学生闭环 — Used-GPU Validation / Purchase Acceptance

硬件门槛：L0 模型/设计主路径；真机实验按页面对应 L1–L3。

成本：0 元教学主路径；不要求购买、拆修或高风险改造。

风险：默认 safe；涉及 PSU/硬件时只做只读调查与厂商手册约束下的正常安装，不做带电拆装。

能力目标

  • 把“GPU 很强”升级成整机层的容量、稳定、供电、散热和长期运行判断。
  • 把 PASS / FAIL / UNKNOWN 与具体 Evidence 对齐。
  • 知道什么情况下应该 BLOCKED 或 REVISE，而不是为了完成课程强行 ACCEPT。

小实验 / 反馈

做 Experiment 86：acceptance model；有真实二手卡时做 Experiment 87：real used-GPU acceptance。

Retrieval Practice

  1. 为什么“游戏跑了十分钟”不是完整 LLM 验收？
  2. 设备 identity、PCIe link、VRAM integrity、错误计数、thermal soak 各自证明什么？
  3. 发现错误后为什么需要保存 raw evidence，而不是只写 REJECT？
  4. 什么证据足以 ACCEPT，什么情况应该 REVIEW 而不是硬判 PASS/FAIL？

完成证据

完成一张 acceptance matrix：identity、link、memory/error、sustained workload、thermal/power、observed anomalies；每项给 ACCEPT/REVIEW/REJECT 与 evidence path。

如何选择 / 迁移

换 GPU、模型或平台后，从 hard gates 重新算，不继承旧机器的 PASS；任何新未知都回到 evidence collection，而不是靠经验口头补齐。

教材补全：二手卡验收是一条证据链，不是一轮压力测试

验收分层

Stage 0: seller claims
Stage 1: physical identity
Stage 2: firmware/runtime identity
Stage 3: VRAM / PCIe / telemetry
Stage 4: representative LLM workload
Stage 5: sustained stability
Stage 6: ACCEPT / REVIEW / REJECT

越靠后的证据越贵，但也越接近“这张卡真的适合你的用途”。

Worked Example：三个证据冲突怎么办？

listing: RTX 3090 24GB
sticker: RTX 3090
runtime: RTX 3090, 24576 MiB
PCI subsystem: unexpected board vendor

这不是自动 REJECT，但应该进入 REVIEW：确认是否换壳、OEM/特殊板、维修替换或识别异常。关键是冲突必须被解释，而不是被平均掉。

验收不能证明的东西

  • 10 分钟稳定不能证明一年 24/7 稳定。
  • LLM workload 稳定不能证明所有显示输出完好。
  • 没有可读 ECC 字段不能证明“0 memory error”。
  • 当前 runtime 能跑不能证明未来所有软件版本都支持。

最值得保存的 Evidence

seller claim snapshot
device identity
VRAM
PCIe max/current
driver/runtime identity
error/event state
benchmark manifest
raw PP/TG
thermal/clock trace
physical notes
final decision + reason

REVIEW 什么时候比 REJECT 更正确？

当证据不足或某字段异常但尚不能证明硬件故障时，REVIEW 能防止“未知=失败”和“未知=通过”两种错误。

Decision Rule

任何与购买目标直接相关的关键 claim——尤其型号、VRAM、普通 workload 稳定性——一旦证据冲突且无法解释，就不能 ACCEPT。

Retrieval Practice

  1. 为什么 seller listing 只能证明“卖家声称了什么”？
  2. 为什么 idle PCIe link 低速不能直接 REJECT？
  3. REVIEW 与 REJECT 的证据条件有什么不同？
  4. 为什么你自己的 LLM workload 比单一通用 stress test 更有购买相关性？

到货 30 分钟、2 小时、长期观察分别能证明什么？

阶段优先目标不能宣称
快速初检identity/VRAM/明显物理异常/基本枚举长期稳定
受控验收代表性 LLM workload、错误/热/clock、重复运行覆盖所有显存地址和接口
后续使用更长时间的真实 workload 可靠性未来永不故障

这能防止“10 分钟没崩 = 全好”和“一个 unsupported telemetry 字段 = 坏卡”两种极端。

Worked Example：卖家说 24 GB，runtime 也显示 24 GB，但持续 TG 逐轮下降

identity/容量已经通过，但 acceptance 还没完成。下一步看 temperature、clock、power limiter、error/event 与环境风道；如果性能在相同 workload 下不可接受地漂移，就按你的 prewritten acceptance policy 进入 REVIEW/REJECT，而不是因为型号正确就接受。

must-match identity:

ACCEPT / REVIEW / REJECT rules:

先写规则能减少“已经到手了就想办法说服自己留下”的沉没成本偏差。

Evidence Preservation

如果出现异常，先保存 seller claim、时间、原始日志/截图、runtime identity、测试命令与状态，再决定是否重测。退货窗口内避免会改变卡况或争议证据的刷 BIOS、拆修、改焊、高风险改造。

What this lesson does NOT prove

本课程的普通 workload 验收不是芯片厂生产测试，也不能保证覆盖每个 VRAM cell、显示口或极端环境。验收目标是为你的 Local LLM 使用建立足够可信、风险可接受的购买 Evidence。
