LLM 架构 6 — 不看跑分，先从 config.json 做一份 Model Dossier

1. 目标不是“算出显存精确值”

目标是先把已知结构整理出来：

模型是谁
→ attention 什么结构
→ KV 多大
→ FFN 多宽
→ 有没有 MoE
→ 权重规模
→ 哪些东西还必须实测

2. 为什么 8B/14B 远远不够？

总参数量不知道：

  • Hq / Hkv；
  • head_dim；
  • FFN expansion；
  • MoE top-k；
  • sliding/local attention；
  • RoPE/context scheme。

这些都会改变本地部署。

7. 权重大小优先用真实 artifact

有 GGUF：

stat
sha256
actual file bytes

没有 exact artifact 才用：

params × effective bpw / 8

并且明确写：

proxy

8. 容量只做 lower bound

lower_bound
=
weights/artifact
+ KV
+ reserve

如果它都已经大于显存：

FAIL-WITHOUT-OFFLOAD

如果小于显存：

POSSIBLE-NOT-PROVEN
公式只能证明“肯定不够”的一部分情况，不能证明 runtime 一定能 fit。

9. 为什么不自动给 PP/TG？

因为 config 只能给 hypothesis：

large dense weights
→ TG bandwidth might matter

large prompt
→ PP matrix/kernel might matter

large Hkv/context
→ KV might matter

MoE
→ expert placement/routing might matter

真正的数字必须进 Experiment 40 实测。
