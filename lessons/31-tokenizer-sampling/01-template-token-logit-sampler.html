LLM 架构 8 — 你输入一句话，模型实际看到了什么？

1. UI 里的消息不是模型输入

你看到：

User: Hello!

模型可能真正收到：

<system>
...
<end>
<user>
Hello!
<end>
<assistant>

或者完全另一套控制格式。

2. 正确数据流

messages
→ chat template
→ rendered prompt
→ tokenizer
→ token IDs
→ model
→ logits
→ sampler
→ next token ID
→ decode text
Chat Template 是模型接口的一部分，不是换皮。

3. 为什么模板错了会影响回答？

Instruction-tuned 模型是在特定控制 token / role 格式上训练的。

你把：

<|user|>
...
<|assistant|>

换成模型没学过的格式，模型看到的 token 序列已经不同。

4. Special Token

常见：

BOS
EOS
system/user/assistant
message start/end
tool call
image/video placeholder

这些 token 的字符串和 ID 都是模型/tokenizer-specific。

5. 双 BOS 陷阱

模板已经生成：

<BOS> ...

你又让 tokenizer：

add_special_tokens=True

可能变成：

<BOS> <BOS> ...

这不是“多一个无所谓”，而是模型输入变了。

6. add_generation_prompt

很多 chat 模型需要最后告诉它：

现在轮到 assistant 开始生成

比如追加一个 assistant header。

漏掉它，prompt 结构可能不完整。

7. Token 数为什么和 GPU 有关系？

template 更长
→ token 数更多
→ Prefill 更多
→ KV 更多
→ context 剩余更少
→ TTFT 可能更长

所以“系统 prompt 只是几段文字”其实是硬件 workload。

8. Tools/RAG 更容易偷走 context

用户只问一句：

查一下天气

runtime 可能还塞进去：

20 个工具 schema
+ JSON 参数定义
+ system policy
+ conversation history

最终 prompt 可能远大于用户输入。

9. Benchmark 要 hash prompt

至少保存：

messages SHA
template SHA
rendered prompt SHA
token IDs SHA
token count

这样以后才能知道两次 benchmark 到底是不是同一个 workload。

10. 模型输出的不是文字

最后一层输出：

logits
=
每个 vocab token 的分数

Sampler 才决定选哪一个 token。

11. Greedy

argmax(logits)

选择最高分 token。

它不需要随机抽样，但不同 kernel 的微小数值差异在极接近的候选上仍可能改变 argmax。

12. Temperature

pᵢ ∝ exp(logitᵢ / T)
  • T 小：更尖锐
  • T 大：更平

T=0 通常由 runtime 特殊处理成 greedy 语义，不是真的除以 0。

13. Top-k 与 Top-p 完全不同

Top-k：

只保留固定 k 个最高候选

Top-p：

按概率排序
保留累计概率达到 p 的最小集合

所以 top-p 每一步留下多少 token 都可能不同。

14. Sampler 有顺序

penalty
→ top-k
→ top-p
→ temperature
→ sample

只是一个例子。

如果顺序变了，结果也可能变。

15. Seed 为什么不是万能复现键？

同 seed 要想复现，还需要：

same token input
same logits
same sampler implementation
same sampler order
same parameters

只写：

seed=42

不够。

16. 和前面所有 Slice 汇合

Chat Template
→ token count
→ PP
→ KV
→ Prefix Cache identity
→ TTFT
→ Sampling
→ end-to-end UX

这就是为什么部署模型时，“Prompt 怎么进模型”必须和 GPU/backend 一样被记录。
