LLM 架构 1 — 一个 token 到底怎么穿过 Decoder-only Transformer？

前面我们已经一直在说 PP、TG、KV、FlashAttention，但如果模型内部数据流没真正画出来，这些词还是散的。

1. Token ID 先变成 hidden vector

tokenizer
→ token ids [B,T]
→ embedding lookup
→ X [B,T,d]

d 是 hidden size。模型内部不是在传汉字/单词，而是在传 d 维向量。

2. 一个现代 decoder block

x
├─ Norm → Attention → + residual → h
└─ Norm → Gated MLP → + residual → y

可以写成：

h = x + Attention(Norm(x))
y = h + MLP(Norm(h))
注意：这是 Llama 风格的简化 pre-norm 心智模型，不是所有 Transformer 的唯一结构。

3. Q/K/V 到底是什么形状？

定义：

  • B：batch/序列数
  • T：这次 forward 的新 token 数
  • d：hidden size
  • Hq：query heads
  • Hkv：KV heads
  • Dh：head dimension
X [B,T,d]

Q [B,Hq,T,Dh]
K [B,Hkv,T,Dh]
V [B,Hkv,T,Dh]

如果 Hkv 小于 Hq，KV cache 会跟着变小。下一节会专门讲 MHA/MQA/GQA。

4. Prefill：整段 prompt 一次进来

假设 prompt 有 2048 token：

X [B,2048,d]
Q [B,Hq,2048,Dh]
K/V [B,Hkv,2048,Dh]

attention 概念上需要：

[2048 queries] × [2048 keys]

所以能形成大矩阵工作，GPU matrix units 更容易吃饱。

这就是 PP 常常非常高的原因之一。

5. 但是别以为一定要在显存写一个完整 2048×2048

数学上有：

scores = QKᵀ

但 FlashAttention 通过 tiling / online softmax 避免把完整 score matrix 反复写到高成本显存。

所以：

数学中存在
!=
runtime 必须 materialize

6. Prefill 同时建立 KV Cache

每层把 prompt 的 K/V 留下来：

K cache [B,Hkv,S,Dh]
V cache [B,Hkv,S,Dh]

于是每 token 的 KV bytes：

2 × layers × Hkv × Dh × bytes

为什么有 2？

因为只有 K 和 V 两份缓存，不是 Q/K/V 三份。

7. Decode：突然变成另一种 shape

Prompt 已经 cached。现在生成下一个 token。

X_new [B,1,d]
Q_new [B,Hq,1,Dh]
K_new [B,Hkv,1,Dh]
V_new [B,Hkv,1,Dh]

但它要读取之前的：

K/V cache [B,Hkv,S,Dh]

attention score 概念形状：

[B,Hq,1,S]

只产生一个 query，却要看整个历史。

8. 为什么 TG 经常看显存带宽？

Decoder block 里的大 weight matrix 还是那些。

但输入从：

T=2048 rows

变成：

T=1 row

同一份权重被用于很少的 token 工作：

低 arithmetic intensity
→ weight streaming 相对更重
→ bandwidth roof 更容易出现

9. 为什么生成不能像 prompt 一样全并行？

logits₀
→ sample token₁
→ forward token₁
→ logits₁
→ sample token₂
→ ...

后一个 token 的输入依赖前一个 token 的输出。

这就是 autoregressive serial dependency。

10. Attention 不是模型全部

每层还有很大的 MLP。

常见 gated MLP：

gate = W_gate x
up   = W_up x
z    = activation(gate) ⊙ up
out  = W_down z

如果 hidden size 是 d、FFN size 是 d_ff，三个大矩阵大约有：

3 × d × d_ff

参数。

所以只把 FlashAttention 优化到极致，也不等于整个 LLM 没别的瓶颈。

11. 最后是 LM Head，不是“直接吐字”

hidden
→ final norm
→ LM head
→ logits [vocab]
→ sampler
→ next token id
→ tokenizer decode
→ text

temperature/top-p 等采样参数在 logits 之后。
