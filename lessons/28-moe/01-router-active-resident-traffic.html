LLM 架构 5 — MoE：总参数很大，为什么每个 token 只算一部分？

1. 先把一句营销话拆成四个数字

看到：

671B total
37B active

绝对不能直接理解成：

只需要装 37B 权重

你必须分开：

总参数
每 token 激活参数
常驻显存
实际搬运字节
这四个数可以差非常大。

2. MoE 本质上先复制很多 FFN Expert

一个 expert 可以先理解成上一节的 SwiGLU：

gate
up
SiLU ×
down

如果一个 expert：

P_expert ≈ 3 d d_e

8 个 expert：

8 × P_expert

全部都属于模型权重。

3. Router 决定当前 token 去哪里

x
→ router
→ scores for expert 0..N-1
→ top-k
→ selected experts

例如：

N = 8
k = 2

一个 token 可能选：

expert 2
expert 6

下一 token 完全可能选：

expert 0
expert 7

4. Top-2 不是“模型只有两个 expert”

它只是说：

这个 token
在这个 MoE layer
执行两个 routed experts

另外 6 个 expert 仍然存在，而且下一 token 可能用到。

5. 所以 active params 为什么小？

如果每个 expert 相同：

total expert params/layer
≈ N × P_expert

而当前 token：

active routed params/layer
≈ k × P_expert

N=8、k=2 时，expert 部分的 active/total 只是：

2 / 8 = 25%

但这不代表 VRAM 只装 25%。

6. 如果所有 expert 都在同一张卡

VRAM
必须容纳
8 个 expert

因为 router 下一步可以突然选任何一个。

Active parameters 是计算选择，不是自动的显存卸载机制。

7. 一个 Mixtral-like 量级

用教学配置：

d = 4096
d_e = 14336
8 experts
top-2
32 MoE layers
4.5 bpw

一个 expert：

176,160,768 weights
≈ 94.5 MiB

一层全部 8 个：

≈ 756 MiB

一层这个 token 选中的两个：

≈ 189 MiB

32 层全部 expert 的权重存储代理：

≈ 23.625 GiB

而 top-2 无复用字节代理：

≈ 5.906 GiB / token

注意：这只是 experts，不是完整模型，也不是实测显存带宽。

8. 为什么 Prefill 会比单 token Decode 好很多？

16 个 token 一起进一个 MoE layer。

它们可能这样路由：

expert 0 ← 4 tokens
expert 1 ← 4 tokens
...
expert 7 ← 4 tokens

runtime 可以把同一 expert 的 token 收到一起：

[4,d]
×
expert weights

而不是把同一套 weight 为四个 token 独立搬四遍。

于是 expert weight 可以在 batch 内摊销。

9. Decode 为什么难？

一个序列每步通常只有一个新 token：

token
→ top-2
→ two expert FFNs

下一 token 路由又可能变。

所以：

  • expert batch 很小；
  • weight reuse 差；
  • 动态 offload 很难隐藏；
  • TG 可能很吃 bandwidth。

10. Routing 越集中越好吗？

不一定。

16 token、top-2，一共 32 次 expert assignment。

完全均衡：

[4,4,4,4,4,4,4,4]

如果全挤 expert 0/1：

[16,16,0,0,0,0,0,0]

后者只碰两套权重，看起来复用很好。

但如果 experts 分布在 4 张 GPU：

GPU0 爆满
GPU1/2/3 闲着

最终延迟可能反而更差。

11. MoE 多卡和 Tensor Parallel 不一样

Expert Parallel 常见过程：

router
→ 把 token hidden state 发给 expert owner
→ expert compute
→ 把结果送回来
→ combine

这是 token dispatch / gather。

所以 PCIe/NVLink/xGMI 再次变成 Roofline。

12. Shared Experts 又是什么？

有些 MoE（例如 DeepSeekMoE 路线）还会有 always-on shared expert。

output
=
shared expert
+
routed top-k experts

这意味着 active expert work 不能只算 top-k routed experts。

13. 为什么 MoE 对垃圾佬特别容易误判？

你看到：

active 13B

以为：

13B dense 的显存需求

结果下载文件几十 B 参数，显存根本放不下，只能 CPU offload。

然后：

router 每 token 改 expert
→ PCIe 搬权重
→ TG 崩掉

这就是：

active compute small
!= local deployment easy

14. MoE 正确评估链

total params
→ expert count
→ top-k + shared
→ expert size
→ resident placement
→ routing distribution
→ expert batching
→ interconnect/offload
→ PP/TG

到这一步，你已经能解释“为什么 MoE 参数巨大但 FLOPs 不同比例增长”，也能解释“为什么它仍然可能非常吃显存”。
